## 1. 产品定义

### 1.1 背景与定位

CM/AM 同时维护多个客户及达人沟通群，重要消息、风险和行动项容易遗漏。本产品是服务 CM/AM 的群聊观察助手：在客户沟通群中静默采集，在内部渠道输出风险告警、TODO 和查询结果；不直接代替 CM/AM 回复客户。

| 场景 | 定义 |
|---|---|
| 客户沟通群 | 客户、达人、CM/AM 的沟通群；信息采集端 |
| 内部渠道 | CM/AM 内部群或指定人员私聊；结果输出端 |

直接用户为 CM 和 AM；客户与达人仅为对话参与者。

### 1.2 产品目标

1. 从机器人入群时开始采集新文本消息，并保留原始依据。
2. 识别情绪、重要度及 P0/P1 风险，及时通知 CM/AM。
3. 自动提取行动项，定时或按需生成优先 TODO。
4. 沉淀可追溯语料，为后续知识库建设提供依据。

### 1.3 非目标

- 在客户群公开内部分析、风险等级或 TODO。
- 自动回复客户、报价、承诺交期或处理付款。
- 跟踪任务认领、处理、完成或真实业务进度。
- 理解图片、语音、视频及复杂附件。
- 回溯入群前的历史消息。
- 建设正式知识库、RAG 或客户自动问答。
- 接入 WhatsApp 等其他渠道。

## 2. MVP 范围与原则

| 模块 | MVP 能力 |
|---|---|
| 消息采集 | 入群即启用，采集新文本消息及元数据，支持编辑/撤回同步 |
| AI 分析 | 角色识别、结构化提取、情绪及 P0–P3 重要度判断 |
| 风险告警 | P0/P1 内部即时告警、确认、等级调整、误报关闭及超时升级 |
| TODO | 06:30–10:00 定时快照，以及 CM/AM 私聊即时查询 |
| 知识沉淀 | 原始语料、结构化事实及未审核候选知识 |
| 基础能力 | 群映射、权限隔离、去重、日志、重试及功能开关 |

核心原则：

1. 机器人成功入群且具备权限后自动启用，无需管理员二次确认；入群时间为采集起点。
2. 入群后发送一次数据采集、AI 分析及未来知识库用途告知，但不阻塞采集。
3. 客户群除首次告知外保持静默；所有内部结果只进入绑定的内部渠道或授权私聊。
4. 未绑定内部渠道时继续采集、分析和存储，但暂停 P0/P1 告警及定时 TODO。
5. 一个客户群绑定一个内部输出目标；多个客户群可汇总到同一内部渠道。
6. AI 结论仅辅助决策；不确定信息标记“待确认”，不得猜测事实。
7. TODO 是参考快照，风险状态是告警状态，均不代表真实处理进度。
8. 候选知识未经人工审核不得用于正式问答或自动回复。

## 3. 总体流程与配置

~~~text
客户沟通群新消息
    ↓
权限校验 → 去重 → 角色识别 → 固定风险规则 → AI 结构化分析
    ├── 原消息、结构化事实和知识候选入库
    ├── P0/P1：内部即时告警
    └── TODO：定时输出或私聊查询
~~~

每个 `source_chat_id` 必须配置：

- `internal_destination_id`
- `owner_cm_am` / `backup_owner_cm_am`
- `escalation_destination_id`
- `timezone`
- `task_scope`

所有查询、提醒、TODO 和知识语料按该映射隔离。

## 4. 功能需求

### FR-001 消息采集与结构化

**采集范围**

- 仅处理机器人入群后的人工文本消息；忽略机器人消息、系统事件和重复事件。
- 保存 `message_id`、群、发送人、角色、租户、时间、消息链接、回复关系及编辑/撤回状态。
- 提取客户/达人、项目、需求、交付物、截止时间、付款、问题、决定、承诺及行动项。

**角色规则**

| 角色 | 处理方式 |
|---|---|
| 客户/达人 | 判断情绪、风险、需求及行动项 |
| CM/AM | 作为上下文，提取内部承诺和待办；不输出“客户情绪” |
| 未知身份 | 保存消息，不输出情绪结论，标记“身份待确认” |

角色只能依据 Lark 身份数据或人工配置，禁止 AI 根据姓名、语气或内容猜测。每条结构化结论必须关联原始消息；消息编辑后重新分析，撤回后停止产生新提醒并同步派生数据状态。

### FR-002 情绪、重要度与风险告警

**情绪标签**

| 标签 | 定义 |
|---|---|
| 正向 / 中性 | 认可、感谢，或普通事实与咨询 |
| 焦虑 | 催促、担忧、紧张或反复确认 |
| 负向 / 愤怒 | 不满、投诉、辱骂、曝光威胁或明显冲突 |
| 无法判断 | 信息不足、上下文不完整或可信度低 |

情绪仅对客户/达人输出，需结合必要上下文，并只在内部渠道展示。

**重要度**

| 等级 | 判断参考 | 系统行为 |
|---|---|---|
| P0 | 人身安全、诈骗、账号/隐私安全、法律威胁、重大投诉 | 立即告警并 @负责人及备份负责人 |
| P1 | 强烈负面、当日截止、付款异常、重要客户、重复催办 | 立即告警并 @负责人 |
| P2 | 常规咨询、资料补充、正常进度 | 记录，可进入摘要/TODO |
| P3 | 感谢、确认收到、无需行动 | 仅记录 |

重要度综合情绪、时限、付款/合同/安全、重复催办、客户标签和行动要求判断，不得仅由情绪决定。

**两阶段告警**

1. 固定规则命中 P0/P1 后，去重并立即发送基础告警，不等待 AI。
2. 基础告警包含来源群、原消息及链接、初步等级、规则原因和时间。
3. AI 完成后更新同一事件/卡片，补充情绪、理由和建议；不得重复告警，等级升高除外。
4. 固定规则未命中但 AI 识别为 P0/P1 时，立即创建事件并告警。
5. AI 超时或格式错误不得延迟、撤回或自动降级基础告警；卡片标记“AI 分析失败或待补充”。
6. AI 不得自动关闭事件；等级调整或误报关闭须由授权人员操作并记录原因。

**告警状态与操作**

| 状态 | 规则 |
|---|---|
| 待确认 | 新建 P0/P1，或已确认事件风险升级 |
| 已确认 | 负责人点击“确认收到”；仅表示已看到告警 |
| 已关闭 | 调整为 P2/P3，或标记为误报/无需提醒 |

MVP 不设置“处理中”或“已解决”。支持“确认收到、调整等级、标记误报”；P0→P1 保留确认状态，待确认事件改用 P1 时限；P0/P1→P2/P3 或误报后关闭。

| 等级 | 确认时限 | 超时行为 |
|---|---|---|
| P0 | 默认 5 分钟 | 再次提醒并升级至内部负责人/值班群 |
| P1 | 默认 30 分钟 | @备份负责人并再次提醒 |

同群同风险主题 10 分钟内合并；风险升级时回到“待确认”并重启计时；已关闭风险再次出现时创建新事件。
负责人不可用时通知备份负责人；两者均不可用时通知独立升级渠道。

### FR-003 TODO 提取与输出

**定位与字段**

- 仅提取需要 CM/AM 或内部团队行动的事项。
- 每项包含标题、来源群、原消息链接、负责人、截止时间、建议优先级和提取理由。
- 缺少负责人或时间时显示“未指定”或“未注明”；缺少消息依据时不生成。
- 相似事项合并去重；系统不跟踪是否完成。

**定时输出**

- 默认数据范围：前一日 10:00 至当前检查时点，可配置。
- 每天 06:30–10:00 按团队时区每 30 分钟生成一次，可配置。
- 每个检查时点均发送最新快照；0 项也发送空状态。
- 数据不可用时显示“TODO 生成失败”，不得伪装为空列表。
- 同一内部渠道、同一检查时点只发送一次；客户群永不接收 TODO。

**排序**

待确认 P0 → 待确认 P1 → 已逾期 → 两小时内到期 → 当天到期 → 其他有截止时间 → 无截止时间。同级按客户/项目标签、重复催办次数及最近消息时间排序。排序由业务规则执行，AI 不得降低 P0/P1 优先级。

### FR-004 私聊即时 TODO 查询

- CM/AM 可询问“现在最要紧的事情是什么”“给我今天的 TODO”或指定客户/项目。
- 默认查询本人负责或备份负责的群、本人 TODO，以及所负责群内负责人未指定的待确认 P0/P1。
- 团队范围需额外授权；对象无法唯一匹配时必须询问，不得猜测。
- 未完成群映射的数据不进入私聊结果。
- 查询使用已入库的风险事件和 TODO，不重复读取全部原始消息；默认沿用定时 TODO 数据范围，待确认 P0/P1 不受时间窗口限制。
- 默认返回 Top 5，包含排序原因、负责人、截止时间、来源链接、生成时间及数据新鲜度；支持继续查看全部或按客户筛选。
- 最近 24 小时“已确认风险”单独展示并注明“实际处理状态未知”，不混入未完成任务。
- AI 仅识别意图和生成说明；权限、筛选及排序由业务代码控制。AI 不可用时使用固定模板。
- 私聊查询不支持创建、修改、完成或删除任务；无数据与读取失败必须明确区分。

### FR-005 知识语料沉淀

从机器人入群时开始保存客户、达人、CM/AM 的新文本对话、回复关系及编辑/撤回状态。机器人输出、系统通知和重复事件不得写入语料池。

| 数据层 | 内容 | MVP 状态 |
|---|---|---|
| 原始语料 | 原文、角色、群、时间、message_id、上下文关系及状态 | 持续入库 |
| 结构化事实 | 客户、项目、需求、问答、决定、承诺、规则、偏好及适用时间 | 自动提取 |
| 候选知识 | 候选问答、流程、政策、客户偏好、项目决定及常见异议 | 默认“未审核” |
| 正式知识 | 经人工确认的内容、范围、有效期及标准答案 | 非 MVP |

规则：

1. 原始对话是依据，不等于已确认事实；候选知识未经审核不得用于正式问答或自动回复。
2. 结构化事实和候选知识必须关联来源消息；无依据则不生成。
3. 客户/项目专属内容默认不得提升为全局知识。
4. 编辑消息时更新派生数据；撤回或删除时标记来源失效并阻止进入正式知识库。
5. 候选提取异步执行，不得阻塞消息入库、风险告警或 TODO；失败可重试。
6. 敏感字段需标记或脱敏；未经批准不得用于训练外部模型。
7. 保留期限、删除和导出权限可配置；删除须传播至结构化记录、候选知识及未来索引。
8. 支持按客户群、项目、时间及角色导出授权范围内的语料。

MVP 不建设向量数据库、RAG、知识审核后台或客户自动问答。

## 5. AI 方案

采用“业务规则 + 单一主模型 + 可切换适配层”。

| 组件 | 职责 |
|---|---|
| 业务代码 | 权限、隔离、去重、风险兜底、排序、定时、发送及状态流转 |
| 大模型 | 结构化提取、情绪/重要度建议、TODO、查询意图及未审核知识候选 |

MVP 主模型为 **OpenAI GPT-5.6 Luna**，保留切换至 **DeepSeek V4 Flash** 的适配层。上线前使用不少于 300 条脱敏中英文及混合语言样本评测，优先比较 P0/P1 召回率、格式稳定性、延迟和成本；合规要求具有一票否决权。

模型约束：

- 仅发送当前消息及同群必要上下文，并最小化敏感数据。
- 输出必须通过 JSON Schema、枚举、类型和长度校验。
- 超时或非法输出最多重试一次，失败后标记“需人工判断”。
- 群消息视为不可信输入，不得改变系统规则或触发工具调用。
- 模型无 Lark 写入权限，不得修改任务、事件或正式知识。
- 缺少稳定事实或来源时，知识候选返回空数组。

## 6. 数据、权限与合规

1. 仅申请所需最小 Lark 权限；只有授权 CM/AM 可查看内部结果及语料。
2. 私聊默认只返回本人负责或被授权群的数据；团队查询需单独授权。
3. 客户群、项目及负责人之间严格隔离，禁止跨客户发送、查询或导出。
4. 入群告知须说明数据采集、AI 分析、保存及未来知识库用途。
5. API Key、Token 和敏感信息不得进入普通日志。
6. 原始语料、结构化事实、候选知识和正式知识分层存储并保持可追溯。
7. 访问、导出、审核、删除和范围变更必须记录审计日志。
8. 数据地域、保留期限、删除机制及模型提供商须通过安全与法务评审。
9. 删除或权限变更须传播至所有派生数据；知识语料不得用于员工绩效或未经批准的外部模型训练。
10. 情绪和重要度不得用于员工绩效或对客户进行人格评价。

## 7. 异常与非功能要求

### 7.1 异常与降级

| 异常 | 系统行为 |
|---|---|
| 未绑定/内部渠道失效 | 继续采集分析并暂存；暂停告警和定时 TODO，通知管理员；禁止回退至客户群 |
| 机器人被移出或消息权限失效 | 停止采集，记录时间并通知管理员 |
| 固定规则命中但 AI 失败 | 保留基础告警，标记 AI 失败，不自动降级 |
| TODO 数据不可用 | 显示失败及最近成功时间，不返回假空列表 |
| 语料入库失败 | 按 message_id 重试并进入失败队列，持续失败时告警 |
| 候选知识提取失败 | 保留原始语料并异步重试，不阻塞其他链路 |
| 消息编辑/撤回/删除 | 更新原始记录及派生数据状态 |
| 重复消息、卡片或定时事件 | 按业务键幂等处理，不重复入库或发送 |
| 未授权查询/导出 | 拒绝请求，不返回数据，并记录审计日志 |

### 7.2 MVP 指标

| 类别 | 指标 |
|---|---|
| 消息分析 | P95 < 8 秒 |
| 固定规则告警 | P95 < 3 秒，且不等待 AI |
| 私聊查询 | 结构化数据可用时 P95 < 5 秒 |
| 语料入库 | 成功率 ≥ 99.9%，失败可重试、可追踪 |
| 知识追溯 | 结构化事实/候选知识关联有效来源比例 100% |
| 隔离与幂等 | 跨客户泄漏、重复入库、重复提醒和机器人回环均为 0 |
| 定时 TODO | 成功率 ≥ 99% |
| 模型质量 | P0 测试集召回率 100%；P0/P1 总召回率目标 ≥ 95% |
| 格式稳定性 | 重试后结构化输出成功率 ≥ 99.9% |
| 告警升级 | 状态可追踪；超时升级成功率 ≥ 99% |

## 8. 验收标准

| ID | 验收结果 |
|---|---|
| AC-01 采集 | 入群即采集一次新文本并记录角色/来源；不回溯历史，不公开内部结果；编辑/撤回正确同步；未绑定内部渠道时只存储不输出 |
| AC-02 风险 | 固定规则命中后不等待 AI 即发送内部基础告警；AI 更新同一事件；AI 失败不撤回或降级告警 |
| AC-03 状态 | 支持待确认、已确认、已关闭；P0→P1 不关闭，P0/P1→P2/P3 或误报才关闭；超时正确升级 |
| AC-04 TODO | 行动项有原消息依据并正确去重排序；06:30–10:00 按配置发送，0 项也发送，失败不伪装为空 |
| AC-05 私聊 | 授权用户获得权限范围内 Top 5 和数据时间；越权拒绝；AI 失败可用固定模板；不跟踪完成状态 |
| AC-06 知识 | 入群后语料持续入库且可追溯；候选默认未审核；编辑/撤回/删除传播；提取失败不影响告警和 TODO |
| AC-07 安全 | 群级隔离、幂等、防回环、权限拒绝、审计及删除传播测试通过 |

## 9. 上线门槛

### 9.1 外部群技术 Spike

正式开发前须验证：

- 企业应用机器人可加入真实或等价跨租户群并持续运行。
- 可接收客户未 @ 机器人的普通文本消息。
- 可可靠区分外部成员与公司 CM/AM。
- 可处理引用、话题、编辑和撤回事件。
- 原消息链接可跳转且不扩大访问权限。
- 机器人移除、群解散或权限回收后可停止采集并告警。

核心能力失败时，MVP 降级为仅处理 @机器人、CM/AM 人工转发或本租户内部群。

参考：[Lark 接收消息事件](https://open.larksuite.com/document/server-docs/im-v1/message/events/receive)

### 9.2 上线检查

- 技术 Spike、群映射及跨群隔离评审通过。
- P0 强制场景无漏判，告警、状态、升级和审计链路通过。
- 定时/私聊 TODO 的排序、空状态、权限和 AI 降级通过。
- 语料入库、来源追溯、撤回失效及删除传播通过。
- 采集、AI、风险提醒、TODO 具备独立开关和可观测日志。
- 数据保存、删除、地域及模型供应商合规评审完成。
- 上线前必须关闭 D-04 数据治理和 D-06 模型供应商决策；其余决策项须在对应开发节点前关闭。
