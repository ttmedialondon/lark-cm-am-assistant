## 判断规则

| 维度 | 作用 |
| --- | --- |
| 近期业务内容 | 主要依据：具体合作机会、报价、直播安排、视频交付及实质推进 |
| 有效互动频率 | 从双方业务证据派生不同交流日期，近 30 天达到 3 天可列为优先；同档再用于排序，不按消息条数计分 |
| 最近业务推进时间 | 近期实质推进优先于旧交流；一般支持不刷新，不使用模型分析时间 |
| 历史合作 | 最后背景参考，旧合作不能永久占据前列 |

聊了很多问候不一定重要；只聊几条，但已在确认具体付费直播，也可以成为重点。投诉、催款、申诉和退出机构进入独立事件紧急度，不凭语气或催促次数抬高维护优先级。

| 档位 | 条件 |
| --- | --- |
| 重点 | 近 7×24 小时有真实、仍有效的具体双边机会或交付安排、实质推进；不要求先证明长期合作，也没有消息数门槛 |
| 优先 | 上述主要事项超过 7 天但仍在近 30×24 小时内，或近 30 个 London 自然日期内有至少 3 个不同的有效双边业务交流日期；频率不能单独升重点 |
| 常规 | 有完整可读的受控正文，但未达到重点／优先，也没有已知超过 30 天的最近相关消息；一般支持、旧合作、已完成交付和单向意向本身不升档 |
| 久未联系 | 当前画像及来源有效、未达到重点／优先，且当前授权内已知最近相关消息超过 30×24 小时；仅描述已同步记录，不表示低价值或合作取消 |
| 待评估 | 尚未完成、来源已失效，或没有可读正文且没有已知旧消息支持久未联系；最近消息未知时不推断沉默，不表示低价值 |

人工档位优先。完结、取消或真实冲突只关闭对应业务对象；其他有效对象保留。沉默不证明合作取消，但旧机会超过窗口不再自动列为当前重点。

默认排序：**重点 → 优先 → 常规 → 久未联系 → 待评估**；同档再按最近推进的 7 天／30 天时效带、近 30 天业务交流日期数、最近推进时间、历史合作、姓名和稳定 ID 排序。推进时间取实际交付／成立／进展与当前具体机会的最新原消息时间，一般业务支持不刷新它。分页前在数据库按保存事实及当前授权消息元数据判断，不解密整段聊天或调用 AI。档位使用滚动 7／30×24 小时；频率按 Europe/London 最近 30 个自然日期去重，沿用双方有效引用的日期，包括双边意向、业务交流与合作事件，单向意向不计日期。这是已提取证据覆盖的业务交流日，不冒充全部聊天的精确频率。

最近相关消息取当前授权内达人本人的发言（含媒体）、CM 发给该达人的私聊及仍有效的已保存受控引用。未指向此人的群广播、已删除、未来或不再有权限的记录不计。仅有旧消息时显示“已同步记录已 N 天无相关消息”及最近消息日期，继续披露同步范围和不可读缺口；没有记录不归为久未联系，空会话覆盖记录也不证明完整同步。

## 事实与取材

- 初次升级重新读取有效授权内近 90 天背景。旧 v1 的自动事实不直接继承，避免保留此前的语义误判。
- 此后按新消息增量更新，合并更新信号、复用相同输入缓存；不每天全库重跑模型。
- 只使用该达人和所选 CM 的授权来源。显式回复补原问题，普通问答最多补四条同会话前文；每批仍最多 80 条、24,000 字符。
- 粗略维护判断不再因未解析 `@` 丢弃其余可读正文；纯 @、标点／表情和缺失回复原文仍不作为有效依据。未知 @ 保留占位，不用于推断人员归属，其他 AI 功能的完整性规则不变。
- 业务对象必须具体。单方广播、群名、寄样、优惠券和机构管理关系不等于成立合作；其他人或其他公司的成果不能算到此人。
- 具体机会和有效互动须有双方证据。完成还须连接成立合作，以及本人实际发布／执行完成的正向见证。一个历史批次可以包括“双方确认后数日完成”；裸链接、ad code 和未来承诺不是完成。
- 空增量不删除原事实。源消息编辑、删除、撤权或身份改绑后，立即使涉及结果失效，定向重新准备材料。
- 每个“达人 × CM”独立评估，不把多个 CM 的聊天相加，也不增加正文权限。

可执行指令、正反例和协议见[维护优先级事实提取协议 v2.0.2](../specs/creator-importance-facts-prompt_v1.0.md)。结构化输出只约束格式，不能保证业务判断正确，因此仍保留语义校验、原文核验和人工调整。

| 表 | 用途 |
