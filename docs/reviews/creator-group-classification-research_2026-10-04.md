# 达人群用途研究与实现

研究日期：2026-10-04。研究材料由当前系统只读导出，使用 Codex 阅读与判断，没有调用 OpenAI 或其他外部模型 API，也没有把研究结论直接写成正式分类。

## 1. 覆盖范围

本轮按当前负责人组合和文本活跃程度分层选取 **120 位已确认达人**，检索他们在数据库中已发现的全部非私聊群，包括当前成员关联和历史发言关联，不先按群名、handle 或自报关键词筛选。

| 范围 | 数量 |
|---|---:|
| 选取的已确认达人 | 120 |
| 达人—群关联 | 414 |
| 去重后的群 | 168，含 147 个普通群、21 个专题群 |
| 群内消息索引 | 54,015 |
| 授权范围内导出的非空 text/post | 36,610 |
| 其中平台删除占位 | 148 |
| 可供研究的业务文本 | 36,462 |
| 无可读业务文字的群 | 4 |

导出没有固定条数截断。33 条空文本没有计入非空记录；图片、附件等非文本索引没有冒充已读正文。148 条占位只表示平台已删除原文，不能恢复或用于判断业务用途。

**取回全部授权材料不等于全文审阅。** 168 个群均已逐群研究；小群读全部当前可读文字，大群按历史序号均匀选取锚点，再阅读邻近消息及可找到的回复上下文。部分记录进行了追加展开。前 60 群用于形成规则，其余 108 群对照复核边界；这是人工定性研究，不是严格盲测，也不是 API 准确率评测。

逐组阅读台账登记 **6,100 条实际阅读记录**，其中 119 条为删除占位，实际阅读业务文本 **5,981 条**。没有把其余 30,481 条业务文本算成已审阅。每群保留结论、正反依据、实际已读消息 ID 与未读范围，研究原始材料和详细台账仅留在受限本地研究目录，不提交到代码仓库。

覆盖方式：79 群读全当前导出文字，85 群分层阅读并补上下文，4 群无正文只读元数据。阅读台账已核对 168 群无重复、无遗漏；B 组后 40 群的已读消息 ID 同时通过实际浏览器记录的数量及有序摘要校验。

“全部群”指这 120 位达人在系统中已经发现的全部相关群，不代表 Lark 中尚未发现、未授权或无法同步的群。成员快照不完整、历史回填未完成、已删除或不可读回复均作为缺口保留，不以现有成员人数推断完整历史。

## 2. 分类方案

每群一个主要用途，另附少量辅助标签。无需为每个品牌和活动增加主类别，也不再使用 CAP/非 CAP。

| 主用途 | 判定依据 | 不应误判的情况 |
|---|---|---|
| 客服群 | 为一个或少数共同合作达人提供账号、样品、广告、优惠券及履约服务 | 推品和培训邀请很多，仍可是专属服务群；多人共同服务不直接排除 |
| 机构达人群 | 面向一批达人的长期综合通知、资源和交流，不限定单一品牌、类目、课程或活动 | 转发某品牌商品，不等于变成该品牌类目群；外部机构用标签注明 |
| 培训群 | 群本身承担课程、任务、作业、录播、成长计划和教学答疑 | 有期限的课程仍是培训；转发别的培训群邀请不算 |
| 类目群 | 围绕明确品类、品牌或产品线长期推品、选品、样品和内容合作 | 品牌群多轮比赛不等于每次都变成活动群 |
| 活动群 | 专为一个明确比赛、活动或项目建立，有专用范围、时间、规则或收尾 | 名称带 Community 也可能只服务一次比赛；活动结束不改变历史用途 |
| 未确认 | 缺证据、真实用途冲突，或商家/机构商务等范围外 | 不等于非达人，也不等于接口调用失败 |

判断看“本群长期服务谁、处理什么”，不是数哪个关键词最多。群名是强辅助证据，要结合开群说明、真实互动和近期变化。没有达人主动说“我是某某”不妨碍识别群用途，但群分类不能反过来证明账号归属或负责人关系。

168 个群的研究分类分布：客服 110、机构达人 7、培训 9、类目 23、活动 9、未确认 10。未确认包括无正文、证据不足和范围外；这些数字是本轮人工研究结果，不是线上队列运行结果。

## 3. 实际发现的边界

以下为研究结论，不是已入库的正式分类；只概括业务事实，不把聊天正文提交到 Git。

| 真实群案例 | 研究判断 | 对规则的影响 |
|---|---|---|
| 个人 handle × TT Media 的专属群 | 客服群 | 跨品牌推品、活动报名、培训邀请是个人服务的组成部分，不能按通知占比改类 |
| shopdirectuk + portialouise0、shopwithcourttt + chickclicksc | 客服群 | 一个群可服务多个 handle 或少数共同合作达人，不设“一群只能有一位达人”门槛 |
| TTMedia Creator Community、Creators Hub | 机构达人群 | 长期综合资源与运营频道，不因某一轮讲座或推品变成课程/类目群 |
| Hypehost Hub | 机构达人群，历史培训标签 | 初期为课程，后来管理员明确改成持续合作机会频道；应识别明确的整体用途转变 |
| AUG Hypehost、RISE、30 Days Growth Sprint | 培训群 | 有期限、分阶段任务或结业答疑，仍以培训为核心；少量后续推品不自动改类 |
| Livestream Masterclass Black Friday | 培训群 | 具体节日期间的短课程，不能仅凭 Black Friday 判成促销活动群 |
| Wonderskin、M·A·C Creators、Dr.Melaxin、colorgram | 类目群＋品牌标签 | 品牌长期上新、样品及多轮合作，与一期活动专群分开 |
| All-In-One Fashion、Women Fashion、FMCG | 类目群＋品类标签 | 多个品牌仍可共享一个明确业务类目；类目群里的比赛/课程只是辅助内容 |
| CEELIKE Creator Community、Missha、St. Tropez | 活动群 | 当前可读历史集中于一期规则、排行榜、奖励和收尾，名称里的 Community 不决定用途 |
| K-Beauty Week、BIOHEAL 线下活动 | 活动群 | 品牌选品、webinar 或 masterclass 服务于一个明确活动，而非长期课程 |
| UK local 综合机会频道、UK TikTok Shop Affiliate Partner | 机构达人群 | 跨品牌、跨品类的长期选品机会，不虚构一个并不存在的专属类目 |
| Shoppable Photo Creator Group | 机构达人群＋平台功能标签 | 长期平台功能交流不等于培训项目 |
| GAMERS ONLY 品牌群 | 类目群＋品牌标签 | 多轮每周挑战、库存、广告和样品合作，不是一场单独活动 |
| OQQ × TTMedia、Real Men × TT Media Apparel、Swappa | 未确认＋范围外 | 商家/机构商务和固定卖家团队协作不能因出现达人或广告码就当达人客服群 |
| 只有名称或几条零散通知的群 | 未确认/等待证据 | 不付费猜测不存在的正文；不足以证明长期用途时保留不确定 |

离开机构、授权撤回、活动过期、群由外部组织运营，是后续发送资格要考虑的事实，不宜强行改写历史群用途。**分类不是发送权限，本轮不实现群发。**

## 4. 已实现的处理流程

1. 在 [API Key 配置](https://larkbot.ttapp.help/admin/ai#creator-group-classification) 新增“达人群用途分类”，独立 Project、模型和加密密钥，默认关闭、没有密钥，不借用其他功能凭证。
2. 保存并启用后，在 [群用途匹配](https://larkbot.ttapp.help/admin/ai/creator-groups) 启动历史待处理群；新群、新达人关系和缺证据群的后续同步触发增量处理。私聊排除，共享群按规范化 chat_id 去重。
3. 本地整理群名、成员结构、角色及当前有效授权文字。单群最多 64 条完整消息、24,000 正文字符，覆盖早期与近期并补真实回复上下文；不把未纳入消息称为已读。在线整理与本轮研究导出的全量材料是不同范围。
4. 使用现有 Responses 调用及严格 JSON 返回用途、置信度、标签、简要理由和材料引用。`unknown` 是正常结果；无可读正文直接等待证据，不请求 API。
5. Owner 查看建议和证据，采纳或人工修改后保存正式用途，可以锁定。正式用途显示在群目录、人员详情的相关会话列表。AI 不能覆盖人工锁定，也不改达人身份、handle 或 CM/AM 关系。

省费用与可靠性：

- 相同群只分析一次；相同材料指纹复用结果。普通新消息不让已通过的稳定用途反复付费，明确变更可主动复查；群名、结构、授权及已有证据变动按有效性校验处理。
- 同步只重新加密相同正文时，复核真实正文哈希，不当作新材料；授权、删除、身份、回复和前文关系仍须有效。
- 复用现有持久化队列及共享 5 并发，不另建线程池，不增加每分钟请求/Token 或每日 Token 预算；遇服务商限额仍按响应退避。
- 请求结果未知时停止自动重发，留待人工复查，避免重复计费。格式损坏与证据不足分开；实际请求 ID、Token、错误码和加密结构化结果留存。
- 材料及结果加密保存；证据查看和人工确认有审计，日志/审计不保存正文。在途配置轮换、停用或授权撤回后，旧结果不能继续进入业务建议，已发生用量仍保留。

固定 Prompt 与 API 协议见 [分类规则 v1.0](../specs/creator-group-classification-prompt_v1.0.md)。`store: false` 不等于自动启用零数据留存，也不替代公司授权和数据处理要求。

## 5. 验证与局限

全套后端 **466 项测试通过，无跳过**，Ruff 静态检查通过。新增真实 PostgreSQL 工作流覆盖独立密钥、去重、私聊排除、人工锁定、Owner/CSRF、同正文重加密、真正修改、未知请求、密钥轮换和撤回授权；既有并发测试补齐六条队列的轮转与共享上限。外部模型传输使用合成测试替身，没有产生研究 API 费用。浏览器检查使用真实模板与合成数据，检查建议/正式分类分离、证据引用、旧结果隐藏和文字转义。

本轮没有真实付费 API 样本，因此不宣称某个模型的分类准确率或实际成本。首次启用后建议先检查返回的真实案例，尤其品牌群与一期活动、培训结业后用途转变、商家团队和共享支持群。规则允许不确定，人工分类是正式业务依据。
