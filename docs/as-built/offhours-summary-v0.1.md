# 下班消息总结试点 v0.1

2026-09-10。需求以[通俗版](../product/message-risk-priority-v1.0.md)为准。新功能默认关闭，发布和测试不自动调用真实模型。

## 入口与执行

- 主人：`/admin/ai#offhours-summary`，配置独立 `offhours_summary` Project、模型和加密 API Key。留空密钥保留原值。
- 保存配置与排队在同一数据库事务中提交；开启后立即排队，worker 自动领取，不需要第二次点击。未开启只保存，不调用。
- 前端：`/dashboard/offhours-summary`。Remi、系统主人可看；指定测试人员还需既有 `creator-review` 查看授权。测试名单编辑权不等于查看权或启动 AI 的权限。
- 固定英国时间 `2026-09-09 18:00` 至 `2026-09-10 12:00`，区间左闭右开。后台可修改，单次最多 7 天；不自动创建下一个日报。

## 如何处理

正式账号归属 → 有权限的相关会话 → 每会话一个独立分析任务 → 结构化事项及 P0–P3 → 前端查看原文。

复用 PostgreSQL 持久任务、租约及现有线程池；`ai_dispatch` 统一统计所有 AI 功能，最多 3 个有效并发。配置关闭、任务替换、授权撤销或消息变化后，旧调用不能提交。重试有限，429 共用限流，配额异常共用暂停，不绕过既有门控。

使用已有 OpenAI Responses 调用，`store: false`，严格 JSON Schema。只输出事项、等级、原因、时段内进展、引用和不确定性，拒答/不完整输出不能视作 P3；服务端再次校验用户、handle、消息引用及工作日条件。接口依据：[结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)，[限流与退避](https://developers.openai.com/api/docs/guides/rate-limits)。

输入指纹基于可读内容和相关范围，正文重复加密、页面刷新不触发重复分析；变化会替换该会话的当前版本，成功的相同输入复用结果。保持开启时每分钟检查，在时段结束后最多继续 24 小时；过期后由主人保存再检查，不无限扫描。

## 范围与安全

- 使用当前 `creator_account_assignments`，不是旧角色/联系人归属。`associated` 只代表人工关联，不推断账号本人；多 handle 未指明时显示横线，不复制事件。
- 模型输入及结果展示均检查 Remi 的有效正文授权、可见可同步会话、授权后的逐条观测和未删除消息；群中未确认人员不自动成为达人。
- 正文和派生总结分别加密；密钥、正文、完整 prompt 不进日志和审计。查看总结留最小审计，撤销权限后停止展示。浏览器不保存本地副本，不直接调用 OpenAI。
- 不生成/发送回复、通知、业务待办，不改达人归属，不关闭业务事件。旧 AI 功能开关保持原状。

## 明确的首版限制

- 最多 300 个**先按正式达人相关性筛过**的会话；每会话 200 条时段消息 + 此前 7 天最多 100 条背景，每条最多 2,000 字符。截断、未同步、模型失败都显示缺口。
- 群聊目前只包含 Remi 和已确认达人发言，不含其他同事回复；不能仅凭这份不完整群上下文触发“三个工作日无人回复”升级。
- 图片/语音/附件不解析，不打开链接。仅凭不可读附件不能定级；可读文字已有明确危机时可保留等级并标资料不全。
- 三天是原请求起第 3 个周一至周五工作日的同一英国时间，不扣法定假日；仅封窗后、私聊历史与同步完整时校验未回复升级，历史不足不臆测无人处理。
- 暂无跨会话或跨日报的长期事件合并、人工改级及每天自动生成。AI 的语义准确率需在主人开启后用真实样本核对；本次工程测试仅用假样本和模拟接口。

新增数据为迁移 `032_offhours_summary.sql` 的设置、运行及任务表；不会清理原聊天或达人关系。发布前按部署手册备份数据库。
