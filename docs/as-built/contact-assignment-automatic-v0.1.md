# 达人负责人匹配与本人确认（当前实现）

状态：**已实现，默认未启用。** 在管理台为“达人负责人匹配”保存独立 OpenAI Project / service-account key 并启用后，worker 才会开始调用模型。当前策略只在发现直接互动后入队；模型始终只生成建议，不直接写入负责人关系。

## 业务规则

负责人是独立于“达人身份”的关系。只有已确认拥有 `creator` 角色、且当前没有负责人记录的联系人会进入匹配；已存在负责人的达人不会再次进入 AI 队列，也不会发生自动交接。

每位达人始终只有一位当前负责人：`contact_assignments` 的部分唯一索引强制 `ended_at IS NULL` 时至多一条记录。人工交接会在同一事务中结束旧记录，再创建新的负责人记录；数据库保留来源、置信度、生效/结束时间和操作审计。没有“备负责人”字段。

## 候选 CM/AM

候选仅来自已接入本系统、`active`、已同意正文同步，且被 owner 在人员详情明确标记为“可担任负责人”的 CM/AM。OAuth 健康状态不是岗位；新授权账号、测试账号和管理账号默认不进入匹配。系统不以管理台角色、群主、群成员共现、昵称或群成员数推定负责人。

某人必须与该达人在同一个已授权可读会话中**双方都有实际发言**，才会成为候选。普通群聊共现只是弱背景；即使模型据此生成高分建议，也必须由被建议人确认后才能进入正式列表：

- 达人侧：该达人任一稳定 Lark `open_id` 发送的消息；
- CM/AM 侧：该授权用户本人发送的消息；
- 与达人直接对应的 P2P 会话是强证据；
- 群聊中只有精确的 `parent_id` 回复关系或稳定 `open_id` 的 @ 提及是强证据；同一话题、同一 root/thread 或群内普通前后发言都不是直接关系；
- 群内其他人的发言不会被送入该候选人的证据包。

系统只评估最近 90 个伦敦**日历日**内的互动，并按最近 30 / 90 天的双向沟通天数、最后互动时间和共同有真实互动的会话数，选取至多 5 名候选供模型比较。业务日期使用 `Europe/London`；“双向沟通天”表示当天双方均有发言，而不是单纯消息总量。

## 送给模型的证据

每个候选最多提供 3 段近期双向片段。普通上下文仅在双方消息相距 72 小时内配对；精确回复或 @ 可跨越该窗口保留。每段带有 `strong`（P2P、回复或 @）或 `weak`（普通群聊背景）标记，且只包含两人的消息，不包含群内其他人。

证据包还包括：

- 每位候选的 30 / 90 天双向沟通天数、共同会话数和最近互动时间；
- 群名仅在每个群会话出现一次，作为弱背景；私聊名称不送入模型；
- 匿名候选代号和可核验的 `M1`、`M2` 消息引用。

不使用话题、交接语句、群成员名单或“谁是群主”等规则。@ 与回复链只用稳定 ID 判断是否存在直接关系，不以文案或显示名称推断。消息正文被明确标为不可信证据，模型不能执行其中的指令。输入最多约 8,000 个正文字符；调用使用 Responses API、`store: false` 与严格 JSON Schema。

## 决策与人工操作

模型只能返回：

- `assign`：明确选择一位候选；
- `needs_review`：有最佳候选，但仍需人工确认；
- `unassigned`：无法支持负责人结论。

模型为 `assign` 或 `needs_review`、候选有效且置信度至少 70% 时，结果会保留为“待人工确认”；低于 70% 或 `unassigned` 视为尚无可靠匹配。

达到管理台“候选推送阈值”（默认且最低 90%）的建议，会出现在被建议 CM/AM 自己的 `/dashboard`“待我确认的达人候选”中。页面只展示达人名称、置信度和建议时间，不向普通用户开放公司级人员目录或其他人的消息正文。

负责人点击“确认由我负责”时，服务端从登录会话取得负责人身份，不接受表单提交任意负责人 ID，并在同一事务内重新校验：这是当前策略下该达人的最新评估且已成功、建议确实指向当前用户、置信度仍达到推送阈值、用户仍可担任负责人、证据仍在授权范围内，且达人仍未被别人确认。校验通过后写入 `contact_assignments`；候选随即从待确认区消失并进入个人“我的达人（正式）”列表。重复提交同一确认是幂等的；交接仍只能由 owner 在联系人详情页人工完成。

上线迁移会结束旧流程曾自动写入的当前负责人关系，并把其当前策略建议恢复为待确认；因此“我的达人（正式）”只代表人工确认后的有效关系。

队列与同步任务共用一个 worker。连续完成 3 个同步任务后，worker 会让 AI 队列运行一项，并在“联系人身份识别”和“负责人匹配”两种 AI 队列之间按实际运行结果公平轮换。负责人队列只从上次检查后新增的消息及有限的重试项找受影响达人，不会每分钟全量扫描所有消息。单条模型失败、限流或格式错误最多只重试该达人当前消息水位 3 次，每次至少间隔 15 分钟，不会暂停其他达人。
