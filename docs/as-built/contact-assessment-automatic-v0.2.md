# 联系人自动识别 v0.2

状态：**已部署。** 本文是联系人 AI 识别的当前运行契约；旧的影子判定文档保留为历史设计记录。

## 目标

在 CM/AM 已授权、且消息正文仍处于可读取范围内的前提下，自动为尚未确定身份的外部联系人生成角色和平台账号关系判断。系统不会发送 Lark 消息，也不会把模型建议用于自动回复。

## 何时入队

Lark 同步任务始终优先。worker 空闲时才补充自动识别任务，每批最多 5 个，随后一次只执行一个任务。

联系人首次满足以下条件时，只要有 **1 条** 有效消息正文即可入队：

- 是非内部 Lark 用户身份（已知外部或尚未归类）；
- 有活动授权、正文同步同意、可见且开启同步的会话；
- 该消息尚未撤回，且正文仍可解密；
- 联系人没有运行中或排队中的同类任务；
- 联系人没有任何已确认角色或已确认平台账号归属。

“已确定”是硬规则：任一 `contact_roles.status = confirmed` 或任一 `contact_social_accounts.status = confirmed` 都会阻止入队。任务真正调用 OpenAI 前和写入结果前会再次检查，因此即使旧任务已排队，也不会为已确定联系人产生新的模型调用。

消息观察使用不可变的首次发现时间作水位；普通的重叠增量同步不会重复触发评估。自动任务的后续策略是：

- 自动确认或待人工处理的结果不会自动重跑；
- 无可执行建议的**成功结果**，只有新增至少 5 条仍在授权范围内的该联系人消息后才会再试；
- 临时失败、无效模型结果或 worker 中断会在同一水位最多自动重试 3 次，每次至少间隔 15 分钟；达到上限后需有新消息才会形成新的重试水位，避免异常时持续消耗额度。

任意一次功能级失败还会暂停整个自动队列 15 分钟；成功后自动恢复。管理员重新保存 AI 配置会清空该连通性状态并允许立即重试。

旧版影子判定的成功结果会迁入“待人工确认”，不会在升级时被静默写成业务事实。

## 证据包与模型调用

每次调用只构造当前仍可读取的最小证据包：命中消息、同一会话前后文、联系人近期发言、账号出现记录、会话类型/群名/租户属性，以及已确认事实。上限为 60 个消息片段、约 32,000 个正文字符。群名只是弱证据，不能单独确认身份。

调用使用 OpenAI Responses API、`gpt-5.6-luna`、`store: false`、严格 JSON Schema。服务端保存经过校验的角色/关系建议、用量和消息引用，不保存 prompt 或模型自由文本。每条建议必须引用实际输入的 `M1` 等消息编号；编号或结构不合法时整次结果作废。

在把正文发送给模型前，以及模型返回后写入前，都会重新检查引用消息的授权、会话可见性和撤回状态。授权范围变化时任务取消，不写入业务事实。

## 决策与人工处理

管理员在 `/admin/ai` 配置自动确认阈值，默认 **90%**（可设为 50%–100%）。

- 达到阈值且不存在事实冲突的角色或 `owner` / `representative` 账号关系，会以 `ai_auto_confirmed` 写入联系人事实；
- 低于阈值或与既有事实冲突的可确认建议，进入 `/admin/ai-candidates`；
- 没有可执行建议（例如模型仅返回信息不足）不会伪造候选或事实；
- 管理员可打开候选查看受当前授权保护的引用证据，逐项人工确认，或将本次候选标记为已处理。

自动确认和人工确认均写入审计日志。页面查看正文、确认和候选处理不记录消息正文到审计日志。

## 边界

- 不自动认定任何人是达人：`creator` 只是一个可确认角色，由阈值和证据共同约束。
- 不从昵称、头像、普通 @ 提及或群成员人数推断账号归属。
- 不评估已确定联系人；如业务事实需要变更，应先由管理员按业务流程修正联系人事实，再决定是否重新评估。
- 不对 Lark 发送消息，不创建机器人回复，不跨越授权可见范围读取正文。
