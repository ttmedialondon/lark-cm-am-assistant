# 用户姓名显示

所有当前用户页面统一使用：**英文名（姓名）**。

- `name=Quanzhen Liang`、`en_name=Remi` → `Remi（Quanzhen Liang）`。
- 两个名字相同 → 只显示一次。忽略多余空格和大小写差异。
- 只有一个名字 → 显示已有名字；两个都没有 → 沿用页面的未命名提示。
- 不翻译、不猜英文名、不按名字合并用户。身份和达人归属仍然使用原来的 ID。

## 数据从哪里来

`lark_identities.name`、`en_name` 分别保留 Lark 提供的字段；`display_name` 只是页面用的组合名称。
OAuth 登录和每轮正常同步的用户资料读取都会更新已授权用户的姓名。群成员同步保留实际返回的字段。
旧消息、旧 @ 信息只能填补缺少的姓名，不得覆盖已取得的姓名资料。
英文名字段没有返回时保留已知值；明确返回空值时清除旧英文名。

当前用户列表、负责人选择、消息发送者、达人联系人和群成员标签使用同一显示规则。
Excel 的负责人匹配同时接受姓名、英文名、组合名和原有人工别名；重名仍进入待确认，不自动串人。
历史导入文件、审计快照和聊天正文保持原样。

## 补齐已有用户

发布前备份，运行迁移 `033_identity_names.sql`。然后运行：

```sh
python scripts/backfill_identity_names.py --apply --owner-id <系统主人ID>
```

脚本遍历所有已存用户，重新计算显示名并同步对应标签，记录汇总审计。只有当前有效授权用户才调用自身资料接口；不会读取无权限会话或改变授权状态。
默认不加 `--apply` 只检查，不调用接口、不写入。
单一身份的联系人可同步姓名；已合并多身份的联系人保留现有标签，避免覆盖人工命名。

已验证的接口限制：用户身份的通讯录详情调用被权限拒绝；应用身份能返回身份 ID，但未返回姓名和英文名。
群成员接口通常也只有 `name`。因此扫描全部已有用户，不等于能取回所有外部用户的英文名；拿不到的保留已有姓名并统计缺口。
不会因为本次姓名更新去增加 Lark 权限、重跑达人识别或改动达人归属。

## 并发与验收

资料响应必须仍属于同一有效授权、同一 open_id 和同一令牌；过期响应不落库。
资料更新失败不阻止消息同步。消息/成员事务不更新授权表，避免与 OAuth 的锁顺序冲突。
检查同名去重、单名回退、旧消息不覆盖英文名、标签一致性、导入别名和授权变更后的响应丢弃。
