## 待确认记录的补填与纠错

流程：填好 handle + 选好 Lark 用户 → 确认入库。

- 缺用户显示“—”，点击“选择用户”展开本人授权范围内的 Lark 用户搜索。只输入姓名不关联，必须选中具体用户；选错可“更换用户”或清除。
- 缺 handle 显示“—”，点击“填写 handle”输入；已有 handle 可点击“修改 handle”。
- 不再要求选择本人 / 代表关系、逐项解除历史疑问、额外勾选确认，也不必先保存或重新检索。点击“确认入库”就是对当前 handle 与用户关联的人工确认；有修改时会先保存，再提交确认。
- “保存草稿”仅供暂时保存，不会入库。确认过程保存失败时不会继续提交；慢响应不覆盖用户继续输入的新资料。
- 缺 handle、未选中具体用户或用户已失效时仍不能入库；系统继续检查重复、正式用户关联冲突和 CM 归属冲突。更正两项后可直接再确认，不必解除旧疑问标签。
- 新的人工确认只表示“此账号关联此用户”，不额外推断用户是达人本人还是代表。已有正式的同一账号 / 用户关系沿用，不覆盖；来源记录和确认前的疑问保留在审计中。
- 仅待确认 / 暂缓记录可修改。正式名单不直接覆盖；普通评审账号只读，下面列明的两个测试账号除外。

确认提交期间整行锁定，刷新列表或迟到的搜索结果也不能改变正在确认的用户。自动化验收覆盖两字段直入库、自动保存、保存失败重试、迟到响应、权限 / 版本 / 冲突校验，以及批量、暂缓和退回；下方发布记录保留各轮验收结果。

## 关键规则

- Excel 先预检再提交。handle / CM / Lark 用户及本人或代表关系明确、有可信稳定 ID 或已核验映射、无风险与冲突时才可直接入库。未知负责人进入管理员待确认，不猜成上传者。
- AI 只生成候选；任何分数都不直接转正。拒答、失败、证据失效都会保留失败状态，不能冒充识别成功。
- 保存草稿不会转正；缺 handle / 用户、同名自由文本、失效联系人 ID、旧版本提交均不能确认。历史 AI 疑问不再要求逐项勾选，由明确的人工“确认入库”一并确认；Excel 自动入库的严格条件不变。
- 正式归属、用户关联、确认审计在一个事务内完成。重复请求不重复入库；一个 handle 最多一个当前 CM；认领一个账号不转走该人的其他账号。
- 新来源冲突保留原正式关系，另放管理员待确认；“不是我负责”退回管理员，不自动推下一人。
- 不恢复旧身份识别 / 旧自动负责人匹配，不做消息回复或风险分级功能。
