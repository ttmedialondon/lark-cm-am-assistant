# Admin Console：当前实现说明

入口：`https://larkbot.ttapp.help/admin`。必须先完成正常 Lark OAuth 登录。

## 访问控制

每个请求都会把 Secure + HttpOnly Web Session 映射回 Lark 授权记录，再查询当前的 `admin_roles` 与 `admin_page_permissions`，不把权限缓存进登录会话：

- 有效 `owner`：系统主人，固定拥有全部页面与管理操作。权限表单不能修改任何 owner 账号，也不能创建或转让主人身份。
- 非 owner：仅可 GET 查看主人明确勾选的页面；原 `operator` / `viewer` 不隐含任何页面权限。所有后台 POST 和联系人 AI 正文证据页仍仅限主人。
- 没有页面权限：仅前台；前台隐藏后台入口，直接访问后台页返回 403。部分授权者访问 `/admin` 时跳转首个获准页面，不读取无权查看的概览。

在“人员”列表或详情展开后台权限设置，勾选后保存；全部取消再保存即撤销全部后台入口。权限修改使用 CSRF 校验、参数白名单及数据库事务，重新校验操作者的主人身份，记录修改前后权限审计。撤销在下一请求生效，后台页面禁止缓存。各页面仅显示获准菜单与跨页链接；非主人不显示管理表单。人员详情中的会话和任务面板、联系人详情中的会话面板另按对应页面权限读取。

9 项可选页面为概览、人员、群聊、消息内容、人员目录、达人、达人归属复核、AI 功能、同步任务。勾选“消息内容”会开放所有已授权人员的可用聊天；只让领导看达人时，应仅勾选“达人归属复核”，不要默认追加全局消息权限。页面权限不改变 Lark 数据源授权、负责人身份或达人归属。

当前部署只写入一个 `owner`；其他已授权 CM/AM 不会自动获得管理台权限。Token、刷新 Token、App Secret 永不由管理台查询或展示。

普通 CM/AM 不需要管理台角色即可在个人 `/dashboard` 查看 AI 高置信度推给自己的达人候选、确认由自己负责，并查看自己的正式达人列表。该入口不开放公司级人员目录或消息正文。

`/admin/messages` 仅展示选定人员在有效消息正文授权后重新观察到的会话消息。只有显式打开有效会话时才读取正文并写一条 `admin_message_content_viewed` 审计，记录查看者、目标授权用户和会话 ID，不保存正文；选择人员、筛选目录或请求无效会话不会自动读取正文。

## 数据模型

```text
authorizations (一个已 OAuth 的 CM / AM；含正文同意时间)
       │ 1:n
authorization_chats (该用户可见会话 + 私有同步游标/状态)
       │ n:1                         │ 1:n
       ▼                             ▼
chats (公司级唯一群聊或私聊)     authorization_message_observations
       │ 1:n                         (该用户见过该消息；是否由该用户发送)
       ▼
chat_messages (公司级唯一消息 ID；加密正文与必要元数据)
       │
       └── lark_identities（发送者 / 成员 / @ 提及的稳定 Lark 身份）──> contacts

chats ──< chat_members（最新群成员快照）
contacts ──< contact_roles（唯一主类别：人工确认或自动确认）
contacts ──< contact_organization_links >── organizations <── organization_tenants
contacts ──< contact_assignments（仅达人：单一当前负责人 + 人工交接历史）
```

同一个 Lark 群被多位 CM/AM 授权时，群元数据和正文只保留一份；每位 CM/AM 的可见性、游标、同步状态和“本人发送”判断仍独立保存。因此，公司级计数不会重复，人员视图也不会误显示未重新授权的正文。

## 页面

| 路径 | 内容 |
|---|---|
| `/dashboard` | 当前登录 CM/AM 的接入状态、高置信度待确认达人候选和“我的达人（正式）”；确认动作只允许接受推给当前用户的最新建议。 |
| `/admin` | 有效授权人数、唯一群/私聊、去重消息、已加密正文，以及“接入进度与需要处理”。未来 5 分钟的定时 job 不计为活动任务。 |
| `/admin/users` | 已接入人员、Lark 接入与后台权限分栏，支持姓名及后台权限筛选；主人在此逐页勾选他人权限。 |
| `/admin/users/{authorization_id}/permissions` | 仅主人 POST：原子替换该非主人账号的页面权限；空列表表示仅前台。 |
| `/admin/users/{authorization_id}` | 某一授权用户的发现/可同步/已完成/等待进度、群/私聊分别的回填比例、当前可见会话与近期任务；owner 可明确标记该账号是否可担任达人负责人。 |
| `/admin/chats` | 公司级唯一群和专题群、已授权可见人数、去重消息数、同步覆盖与成员人数状态。 |
| `/admin/messages` | 需消息内容权限：先选人员，再按名称/群聊/私聊查找会话；会话每页 20 项，正文按最近 100 条分段、页内正序阅读。 |
| `/admin/contacts` | 需人员目录权限：查看联系人和组织资料；联系人 AI 正文证据仍仅限主人。 |
| `/admin/creators` | 需达人权限：查看已确认拥有 `creator` 角色的联系人及其稳定 Lark 身份。 |
| `/admin/creator-review` | 需达人归属复核权限：按 handle、联系人姓名、当前负责人及留存依据筛选已确认达人；区分人数与账号数、系统归属与主证据留存情况。 |
| `/admin/creator-review/{contact_id}` | 需达人归属复核权限：展示手动导入依据及受限会话；不提供负责人变更、权限分配或导出操作。 |
| `/admin/contacts/{open_id}`（达人） | 需人员目录权限：查看资料及负责人；人工确认、交接与组织修改仅限主人。 |
| `/admin/ai` | 需 AI 功能权限查看配置；保存、轮换密钥和恢复队列仅限主人。 |
| `/admin/jobs` | 最近同步任务及不含敏感内容的运行统计。 |

## 消息阅读工作区

来源选择、会话目录与记录阅读分区展示，保持原生 GET 链接与表单。切换人员清空会话及筛选；筛选重置会话和目录页；换会话从最近记录开始；目录翻页保留已打开记录，并在当前会话不在列表本页时明确提示。列表仍按名称排序，独立滚动；人员不在选项分页时只读取其资料，不附带查询会话和任务。

正文仍只取当前有效授权范围内已保存的加密正文，不追取其他来源、未保存内容或附件原件。数据库按时间及 ID 倒序选择最近一段，取最多 100 条后反转为页内时间正序，以日期分隔；通过“更早记录 / 更新记录 / 回到最新”切换，清楚标注第 1 页是最近记录。发送者为所选人员时显示其姓名，不用容易与查看者混淆的“本人”。目录的已存正文数与当前正文范围对照，历史索引不当作可读正文数。来源停用、缺正文授权、无会话、筛选无结果、失效会话及暂无正文分别提示，不推断未保存记录的原因。

## 达人归属复核试用版

列表与详情保留页面导航，入口严格对应当前账号获准的页面：单项权限显示一个入口，多项显示对应多个，主人显示全部。复用后台同一份权限菜单，不额外开放页面；达人复核页不显示全站品牌头、管理台标题、登录者身份或预览标签。共享导航也不显示角色及权限说明，避免切换页面后在导航中重新出现身份权限字样。失效链接和访问受限提示仍返回达人复核。此调整仅影响展示，登录、逐页授权、数据范围及审计照常执行，人员页的权限设置功能保持原样。

入口由系统主人逐页授权，迁移不会自动给任何其他账号开权限。名单仅取已确认主角色为 creator 的联系人。导入审计中的 handle、Excel 行和身份依据用于说明来源；没有留存的字段明确标注，历史 P2P 导入不会仅凭已确认角色显示为主证据完整。列表只统计已入库联系人，不代表 Excel 中尚未定位的账号总量。

### 账号整理交接

正式复核页把“依据已归档”“依据未完整归档”和“匹配待确认”分别显示、筛选；保留 `evidence=review` 作为全部待处理的旧链接。handle 保存读取和搜索统一处理外围空格、前导 `@` 和大小写；不同标点不擅自合并。归档判定要求当前同一决策覆盖每个展示 handle，不再用最新一条证据替全部历史账号背书。

`/admin/creator-review/preparation` 是仅系统主人可查看的只读交接清单。普通复核权限不包括该入口，非主人在查询前即拒绝；不新增后台权限项，不开放候选聊天。台账每个 handle 一行，列明 Excel 源行、分开的 CM / TAP CM、源群名、正式或建议联系人、未处理原因与下一步。候选关系不进入正式达人列表，没有确认或修改归属的 POST 接口，最终选择由用户另行处理。

台账使用既有 `audit_events` 追加冻结版本（`creator_handle_roster_prepared`），不修改历史审计、角色、负责人或正式 handle。三类为已归档、未完整归档、待人工判断；后者可包含未定联系人、漏记别名和已入库但身份存疑的记录。仅风险条目另存按正式联系人限定的注释（`creator_handle_identity_review_flagged`）；普通复核查询只投影该联系人在最新批次下的风险注释，不读取全部候选清单。

每个既有或建议联系人绑定准备时的角色来源、角色更新时间、当前关联 ID 及负责人 ID；变化后显示需重核，旧注释不沿用。候选 handle 已出现在正式名单、原映射不再存在或原已归档依据不再完整时，同样标为过期。准备快照不能把原本未归档的正式记录提升为已归档。

发布脚本 `backend/scripts/prepare_creator_handoff.py` 默认只校验并回滚，`--apply` 才追加台账及风险注释。输入 JSON 留在 Git 外，必须提供文件 SHA-256 和当前有效主人 ID，并执行部署手册备份门槛；发布时重核正式 handle 全量覆盖、状态绑定、两个 AI 开关关闭且无相关任务。相同内容重跑不重复追加；原 Excel 和旧报告保留，交接清单单独标为当前入口。

聊天通过该达人详情单独限定范围，与主证据完整性及当前负责人解耦。左侧汇总所有有效授权来源下与该达人精确身份关联的群聊和单聊，显示记录数、最近记录和授权来源；不按群名、handle 相似度扩展范围。群聊关联来自仍有效来源观察到的成员事实或该达人已获授权的发言；成员事实不等同于当前在群。单聊要求准确对端身份。每次会话、计数及正文查询重新校验正式达人角色、外部用户身份、来源授权/正文同意、会话可见且启用、正常状态和同意后的消息观察记录。多人同步的同一会话和消息只展示一次。

会话内展示各参与者的已同步授权记录，不再只筛选达人和当前负责人。文字、富文本及卡片中的已保存文字复用原有文本渲染；缺正文及无文本的媒体保留明确占位，不读取附件原件，也不追取引用中的其他会话。历史归属证据不足的达人仍可人工查阅；单聊依然不能独立决定归属。明显邮箱和电话号码做基础遮盖，自由文本可能包含其他参与者及业务信息，不保证完整脱敏。供主人及已获达人归属复核页面权限的人员查看，不声称涵盖未同步或已删除的历史。

正文请求写入 `creator_review_messages_viewed` 审计，只记录查看者、达人和会话标识；响应禁止缓存。页面不修改达人角色、负责人关系或 AI 配置。主人可在人员页勾选开放本页，而不开放全局聊天页。

## 当前同步参数

- 首次回填：Lark API 可返回的全部历史；
- 增量同步：每 5 分钟；
- 去重回看窗口：10 分钟；
- 每个授权用户：同一时刻最多一个 worker 任务；
- 正文：新版授权后 AES-GCM 加密存储，不进日志；
- 私聊：以 `types=p2p` 尝试发现，状态会在用户记录上可见，失败不会影响群聊。
- 群成员：每次成员刷新分页更新最新快照；Lark 未返回的成员不会被删除或标为离群。
- 首次历史回填：安全分页续跑属于同一个 job，不记为错误重试；`attempts` 只在临时错误、租约过期或退避重试时增加。
- 已归档/解散会话：保留发现事实但不计划回填，并从“可同步会话”分母中排除。
- 专题群：计入群聊总数，在目录与人员页单独标为“专题群”。
- 人员主类别、组织归属、达人负责人相互独立。待识别不等于“其他外部联系人”；群名只是弱证据，不能单独确认类别或组织。Lark 关联租户只能验证 `tenant_key → 组织`，不自动证明该人是该机构员工或负责人。
