# 后台权限与用户显示

核对日期：2026-09-11。本文说明现有规则，不新增权限，也不代表历史名单仍然有效。

## 1. 谁能进后台

- 系统主人拥有全部后台页面和管理操作，但也要正常登录，且账号授权有效。
- 其他人只能看主人勾选的页面。以前的 operator / viewer 身份不会自动带来页面权限。
- 一个权限都没有，就只有前台；后台入口隐藏，直接输入后台网址也不能进入。
- 主人在“人员”列表或详情里勾选、保存。全部取消，就是撤销全部后台页面权限。
- 权限保存后，下一个请求立即按新权限检查，不需要退出重登。
- 这个表单不能取消、创建或转让系统主人身份。

## 2. 可以勾选哪些页面

| 页面 | 能看什么 |
|---|---|
| 概览 | 系统接入、数据量和同步概况 |
| 人员 | 已接入人员、接入情况和后台权限 |
| 群聊 | 会话目录、成员及同步情况 |
| 消息内容 | 所有已授权人员的可用聊天，包含非达人 |
| 人员目录 | 联系人身份、组织和关联资料 |
| AI 功能 | 功能设置和运行配置；非主人不能保存修改 |
| 同步任务 | 同步任务及运行情况 |

导航只显示已获准的入口：开一个显示一个，开多个显示多个。没有概览权限时，进入 `/admin` 会跳到第一个获准页面。
后台“达人”“达人归属复核”及其详情、聊天查看、整理清单已移除；旧地址返回 404，对应权限不再可勾选。迁移只清理这两项旧页面权限并记录审计，不删除达人或聊天数据，也不自动改授其他页面。

## 3. 能看，不等于能改

后台页面授权是只读权限（GET）。修改权限、配置 AI、修改联系人等后台操作，仍只允许系统主人；旧交接负责人操作已移除。
联系人 AI 正文证据页仅限主人，不随普通页面权限开放。

旧前台达人名单 `/dashboard/creators` 及导入、核对、扫描和确认接口已移除，直接访问返回 404。旧 CM 资格编辑和联系人负责人分配入口一并移除；数据库原有资格、名单和归属数据保留。新的 CM 编辑规则待确定，不自动恢复测试者的旧业务入口。

## 4. 领导看聊天，范围要分清

后台“消息内容”仍按所选授权人员当前可读范围展示，不只限达人。当前没有“只看达人聊天”的专用页面；旧前台候选证据接口也已移除，不能用开放“消息内容”替代这一限制。

## 5. 搜到用户，不代表能读他所有消息

旧前台补选用户搜索已移除。目录搜索和正文阅读仍分别校验；看到姓名、出现在同一个群，或者被别人 @，都不会新增聊天访问权。
正文只来自当前有效授权、已同意读取正文、仍可见且启用的会话，以及同意后有效观察到的消息。
未保存或已删除的正文不能查看；不读取附件原件，不沿引用或链接扩大到别的会话。
页面权限不会替代 Lark 授权，系统主人也不会凭后台身份绕过这些数据边界。

## 6. 查看和修改会留下记录

权限变更记录操作者、目标人员及修改前后的权限。
明确打开聊天正文时，记录查看者、达人或目标授权用户、会话等标识；审计不保存聊天正文。
仅筛选目录不会自动读取正文。权限与正文页面禁止缓存，接口每次重新检查当前权限和数据范围。
消息解密密钥、用户令牌和应用密钥不在页面展示。

## 7. 姓名怎么显示

统一按“英文名（姓名）”显示，例如 **Remi（Quanzhen Liang）**。
两个名字相同只显示一次，忽略多余空格和大小写；只有一个就用已有名字，没有则显示未命名提示。
Lark 若确实返回 `user805550`，就保留它，不根据 handle 猜姓名。消息里的 `@_user_1` 只按该条消息保存的明确映射还原，无法确定时保留提示。
显示名可以更新，但用户关联始终依靠稳定 ID；不因同名合并用户、不改变达人归属。

人员目录在姓名左侧显示小圆头像，不新增一列。头像只来自 Lark 官方资料，并按该行的 Lark 用户 ID 保存；多身份人员不借用另一个身份的头像。没有头像、无读取权限或图片加载失败时显示姓名首字母，不显示破图。

后台每天检查一次，读取页面只使用已保存的资料，不现场请求全库头像，也不调用 OpenAI。先验证已授权 CM、内部同事和外部达人样本，再扩大范围；接口缺权限时退避重试，不把“接口成功但未返回头像”算成补齐成功。
