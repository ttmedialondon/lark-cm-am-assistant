# 后台权限与用户显示

核对日期：2026-09-11。本文说明现有规则，不新增权限，也不代表历史名单仍然有效。

## 1. 谁能进后台

- 系统主人拥有全部后台页面和管理操作，但也要正常登录，且账号授权有效。
- 其他人只能看主人勾选的页面。以前的 operator / viewer 身份不会自动带来页面权限。
- 一个权限都没有，就只有前台；后台入口隐藏，直接输入后台网址也不能进入。
- 主人在“人员”列表或详情里勾选、保存。全部取消，就是撤销全部后台页面权限。
- 权限保存后，下一个请求立即按新权限检查，不需要退出重登。
- 这个表单不能取消、创建或转让系统主人身份。

## 2. 可以勾选哪些页面

| 页面 | 能看什么 |
|---|---|
| 概览 | 系统接入、数据量和同步概况 |
| 人员 | 已接入人员、接入情况和后台权限 |
| 群聊 | 会话目录、成员及同步情况 |
| 消息内容 | 所有已授权人员的可用聊天，包含非达人 |
| 人员目录 | 联系人身份、组织和关联资料 |
| AI 功能 | 功能设置、运行配置和第二步达人归属判断；非主人只读 |
| 同步任务 | 同步任务及运行情况 |

导航只显示已获准的入口：开一个显示一个，开多个显示多个。没有概览权限时，进入 `/admin` 会跳到第一个获准页面。
后台“达人”“达人归属复核”及其详情、聊天查看、整理清单已移除；旧地址返回 404，对应权限不再可勾选。迁移只清理这两项旧页面权限并记录审计，不删除达人或聊天数据，也不自动改授其他页面。

## 3. 能看，不等于能改

后台页面授权是只读权限（GET）。修改权限、配置 AI、修改联系人等后台操作，仍只允许系统主人；旧交接负责人操作已移除。
联系人 AI 正文证据页仅限主人，不随普通页面权限开放。

旧前台达人名单 `/dashboard/creators` 及导入、核对、扫描和确认接口已移除，直接访问返回 404。旧 CM 资格编辑和联系人负责人分配入口一并移除；数据库原有资格、名单和归属数据保留，不自动恢复测试者的旧业务入口。

第二步临时页 `/admin/ai/creator-ownership` 及只读数据接口归入现有 AI 页面权限。预筛选、开始/暂停/继续及暂缓仅主人，均校验当前权限和 CSRF；单独原文证据入口也仅主人。直接确认入库入口关闭。其他查看者只看到安全结果字段，不解密原文及派生详细说明。选择某位 CM 不增加正文访问权。

新版前台 `/creators` 不要求后台页面权限。有效授权 CM 只能查看、补填、确认或暂缓自己的候选，查看自己的正式达人；证据限于该 CM 当前可读来源。主人可选择 CM、准备/启动/暂停扫描及保存自动入库开关。Shang Ma 不继承旧 Remi 测试编辑特权。所有操作在服务端重新校验身份、范围和 CSRF，不能只靠隐藏按钮。

群发是独立前台权限，不通过后台页面勾选开放。Owner 默认可用；普通用户需单独开通 `authorizations.broadcast_enabled`，只能使用本人的正式达人、本人可见的已分类群和个人名单／消息模板。跨 CM 查看或达人管理权限不会扩大群发范围。缺少 Lark 发送授权时，由用户本人完成增量 OAuth；功能开关不修改已有后台权限、消息来源或授权 scope，当前仍只预览，不实际发送。许可变更需记录审计，撤销后下一个请求立即生效。

## 4. 领导看聊天，范围要分清

后台“消息内容”仍按所选授权人员当前可读范围展示，不只限达人。当前没有“只看达人聊天”的专用页面；旧前台候选证据接口也已移除，不能用开放“消息内容”替代这一限制。

2026-09-14：Shang Ma 的“消息内容”限定为 Remi。来源列表仅显示 Remi，服务端在查询会话与正文前拒绝其他来源 ID；群聊和私聊仍受 Remi 当前授权及正文可读范围限制。该限制保存在 `admin_message_source_limits`，独立于页面勾选，重新保存页面权限不会解除限制。系统主人不受此限制，跨 CM 达人名单权限不受影响。

2026-09-17：按主人要求，Shang Ma 的消息来源范围扩展为 Remi、Nero、Janette、Jenette Z、Mona 五位。`admin_message_source_limits` 以查看者和来源的组合为主键，保留原有限制并增加四位来源；来源列表与服务端校验使用同一名单，其他人员及未来新增 CM 不自动开放。仍只读，群聊和私聊受各来源当前授权及正文可读范围限制；页面权限保存不会清除来源名单。

## 5. 搜到用户，不代表能读他所有消息

旧前台补选用户搜索已移除。目录搜索和正文阅读仍分别校验；看到姓名、出现在同一个群，或者被别人 @，都不会新增聊天访问权。
正文只来自当前有效授权、已同意读取正文、仍可见且启用的会话，以及同意后有效观察到的消息。
未保存或已删除的正文不能查看；不读取附件原件，不沿引用或链接扩大到别的会话。
页面权限不会替代 Lark 授权，系统主人也不会凭后台身份绕过这些数据边界。

## 6. 查看和修改会留下记录

权限变更记录操作者、目标人员及修改前后的权限。
明确打开聊天正文时，记录查看者、达人或目标授权用户、会话等标识；审计不保存聊天正文。
仅筛选目录不会自动读取正文。权限与正文页面禁止缓存，接口每次重新检查当前权限和数据范围。
消息解密密钥、用户令牌和应用密钥不在页面展示。

## 7. 姓名怎么显示

统一按“英文名（姓名）”显示，例如 **Remi（Quanzhen Liang）**。
两个名字相同只显示一次，忽略多余空格和大小写；只有一个就用已有名字，没有则显示未命名提示。
Lark 若确实返回 `user805550`，就保留它，不根据 handle 猜姓名。消息里的 `@_user_1` 只按该条消息保存的明确映射还原，无法确定时保留提示。
显示名可以更新，但用户关联始终依靠稳定 ID；不因同名合并用户、不改变达人归属。

人员目录在姓名左侧显示小圆头像，不新增一列。头像只来自 Lark 官方资料，并按该行的 Lark 用户 ID 保存；多身份人员不借用另一个身份的头像。没有头像、无读取权限或图片加载失败时显示姓名首字母，不显示破图。

后台每天检查一次，读取页面只使用已保存的资料，不现场请求全库头像，也不调用 OpenAI。先验证已授权 CM、内部同事和外部达人样本，再扩大范围；接口缺权限时退避重试，不把“接口成功但未返回头像”算成补齐成功。

获取更多人员资料需 CM 同意 `contact:contact.base:readonly` 和 `contact:user.base:readonly`。应用开通不等于用户已经授权；回调按实际返回的 scope 验证。外部联系人资料成功且身份、授权校验通过时，同步原名/英文名，即使没有返回头像也保留有效姓名；不覆盖已 OAuth 授权人员的本人资料来源。资料仍受 Lark 可见范围限制，不保证外部用户一定返回真名或头像。

2026-09-14：新增独立的 `creator-manage`（达人完整管理）权限，授予 Shang Ma。此权限在 `/creators` 内允许跨 CM 查看正式达人、候选和证据链，导入 CAP 名单、启动/暂停/恢复/重新扫描，以及修改核对、确认入库和暂缓。上传者与负责人分别记录，当前来源可读校验、冲突检查和 CSRF 继续生效；撤销权限后下一次请求立即拒绝跨 CM 操作。它不授予系统主人身份、后台配置权或其他消息来源访问权；Shang Ma 的“消息内容”仍仅限 Remi。已停用的旧扫描入口仍停用。

## 全量文字记录下载

在“消息内容”选择一位聊天授权来源后，点击“下载全部聊天记录”。无需选择会话或时间，当前页面筛选不会影响导出。下载 ZIP，每个可读私聊或群聊各一份 Excel，仅含英国当地发送时间（含时区偏移）、发送人、消息内容。文字及富文本中的文字按时间升序导出，不下载图片、文件或语音。全量指系统已同步且仍有权读取的记录。

下载沿用消息页面权限及获准的 CM 来源范围，并核对有效正文同意、会话可见性、同步开关、消息观察时间和删除状态。按会话生成 Excel 并流式发送 ZIP，浏览器可显示已下载大小；最终大小未知，不显示准确百分比。每个会话发送前复核人员授权和访问权限；中断或失败时不发送完整 ZIP 结束目录，需要重新下载。导出完成记录来源及数量，不把正文写入审计；临时文件在使用后清理。超过单元格长度的正文分行保存，保留完整文字；聊天内容按字符串写入，避免被 Excel 执行成公式。

消息页面的人员选择器只读取姓名和授权状态，不再计算消息、会话和同步任务统计。人员管理页面的统计保持原样。

## 页面与查询精简（2026-09-21）

人员统计只聚合当前页的授权来源；按观察记录排除已删除消息，保留原有可见范围和去重口径。人员详情先分页会话再统计。联系人目录的全局分类数、筛选总数和当前页共用一次目录查询；当页联系人活动数据批量读取。达人名单批量读取身份与 handle，已入库页不加载候选明细。

会话活跃时间最多每五分钟更新一次；每个请求和每个导出会话的权限复核照常执行，不缓存授权。消息显示名的只读查询不再锁定身份记录。归属判断与总结页面在活跃任务期间保持原刷新频率，结束后降为约一分钟复核；每次仍验证当前权限与材料，无变化时返回无正文的 304、不重绘页面。总结只在单次请求内复用同一源会话的校验结果，不跨请求缓存正文。

重复提示删除，技术说明折叠；密钥更换、API 费用、权限设置、失败和资料不完整提示保留。两个达人权限共用一个“达人名单”导航入口，权限配置和服务端边界不合并。
