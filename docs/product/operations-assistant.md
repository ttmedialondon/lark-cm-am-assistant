# 运营对话助手

更新日期：2026-10-12。

## 使用

工作台、我的达人、群发和消息总结页面右下角的“问助手”打开聊天浮窗，可全屏。支持查询达人、指定时段消息总结、筛选事件、追问最新进展、展开原文和起草回复；不发送消息、不修改人员或负责人关系。

所有提问先交给模型选择工具，不按关键词预先分发。默认查询当前 CM 的正式达人及授权相关聊天；页面选择的 CM 会带入助手，服务端仍按现有消息总结权限核验。姓名重名时列候选，其他正常查询不逐次确认。

“今天上午”默认英国当天 00:00–12:00，实际截止不晚于提问提交时间；可以直接指定其他时间。原时段结论与后来进展分开展示，回复情况与解决状态独立。较长范围按不超过七天的窗口处理，保留窗口标签，不宣称跨窗口事项已经全局去重。

主题检索筛选已有事件，不是全量历史正文搜索。原文显示聊天、发送人、时间及问答；未同步、不可读取和附件缺口保持可见。

回复建议沿用已有取材、筛选、风格和翻译流程，只提供可编辑草稿和中文参考。编辑后中文仍为生成原稿的参考，复制只复制当前正文。生成、编辑和复制不改变事件状态。

## 配置与执行

AI 配置页新增 `operations_assistant`，默认 `gpt-6-luna`，由 Owner 填写独立 Project ID、服务账号 Key 并启用。凭证加密且不回显；编排、临时分析和助手起草均使用本配置，旧总结与其他功能不换 Key。

仅新增 `assistant_sessions`、`assistant_turns` 两表。临时分析复用现有总结和回复任务，以 `origin` 区分，不修改全局设置，不出现在固定时段页面。

客户端首次发送前保存会话和请求 UUID；响应丢失时复用两个编号。后台持久执行，刷新和 SSE 重连只恢复进度。收起不停止，停止只影响本轮和专属任务；已提交请求可能计费，迟到回执保留但不展示。

等待子任务时释放 AI 并发名额，完成后按原 call ID 将结果交回模型，不让模型轮询。接现有共享五并发和轮转调度，不增加日 token、TPM 或 RPM 预算。相同工具参数在本轮复用；相同材料的未知调用不自动重发。

历史回答和原文重新打开、进入下一轮上下文时复核权限与材料；撤权或材料变化的旧内容不继续展示。正文和工具检查点加密，日志与审计不保存正文或密钥。

## 接口与实现

| 接口 | 功能 |
|---|---|
| `POST /assistant/turns` | 提交提问，202返回会话与请求引用 |
| `GET /assistant/sessions/{id}` | 恢复本人对话 |
| `GET /assistant/turns/{id}/events` | SSE读取范围、进度、答案和终态 |
| `POST /assistant/turns/{id}/cancel` | 停止本轮 |
| `GET /assistant/evidence/{ref}` | 展开仍有权读取的原文 |

五个工具为 `find_creators`、`summarize_messages`、`filter_events`、`read_event_context`、`draft_reply`。Responses使用严格参数和 `store:false`，服务端保存必要响应项和工具结果，不依赖供应商托管会话。

实现位于 `backend/app/assistant.py`、`assistant_tools.py`、`assistant_routes.py` 和对应原生 JS／Jinja 组件。继续使用既有 PostgreSQL worker，不新增 Agent 框架、中间件或向量库。
