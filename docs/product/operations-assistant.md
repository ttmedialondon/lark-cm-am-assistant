# 运营对话助手

更新日期：2026-10-12。

## 使用

工作台、我的达人、群发和消息总结页面右下角的“问助手”打开右侧抽屉，可全屏。支持达人资料、群目录、业务消息检索、活动统计和同步状态，原有总结、追问与回复建议继续保留；不发送消息、不修改人员或负责人关系。

“我的达人”每位已分配达人旁可直接询问账号、负责人和维护情况。聊天显示资料卡、群列表、消息命中和统计表；原文在独立阅读区展开，手机为单列阅读层。阅读旧内容时不强制滚到底，新结果用按钮提示。手动草稿不被刷新结果覆盖；不新增跨刷新草稿保存、历史管理或长期记忆。

所有提问先交给模型选择工具，不按关键词预先分发。聊天总结、原文检索和消息统计默认覆盖当前 CM 已授权可读的全部群聊、私聊与发言人，包括未识别、未分配联系人及机器人消息，不要求对方先成为达人。只有明确要求达人、指定达人或追问这些达人时，才使用正式达人范围。页面选择的 CM 会带入助手。Owner 可在助手内选择任一 active、已同意正文采集的人员，普通用户只能选择本人；查询时服务端再次核验，旧达人试点权限不扩大为其他员工全量消息权限。切人开启空白会话、清除上一人的卡片和原文，不带入其上下文，也不自动调用模型。无页面选择时默认本人，不再隐式选择 Remi；Owner 本人尚无正文授权时使用列表首个有效人员。姓名重名时列候选，其他正常查询不逐次确认。

“今天上午”默认英国当天 00:00–12:00，实际截止不晚于提问提交时间；可以直接指定其他时间。原时段结论与后来进展分开展示，回复情况与解决状态独立。较长范围按不超过七天的窗口处理，保留窗口标签，不宣称跨窗口事项已经全局去重。

“我负责的达人有哪些未回复事项”使用专用 `query_unreplied_creator_events`，不先让模型分页挑人。默认固定本轮当前 CM 的完整正式负责名单；页面明确选择达人时仅用该选择。后台复用现有时段分析，筛选未见已接入 CM/AM 回复的事项，先按达人重要度、再按事项紧急程度排序。重点优先不排除常规达人，未回复也不等于未解决。每项展示达人、群聊／私聊来源和概括，保留原文入口。该结果是已抽取的事项，不是对每条原消息无人回复的绝对证明；不可读附件和同步缺口仍说明。

专用查询最多向编排模型提供 25 项预览和完整匹配数量，后端自动附出本轮全部匹配卡片，不要求模型逐页读名单或输出数百个长引用。部分分析、失效材料或来源缺口不能冒充全范围无未回复事项；原时段以提交时刻为截止，不包含未来回复。完整范围中有多少人负责、实际读到多少消息、匹配多少事项分别计数。当前模式仍可能需要新增该时段的分析任务，不自动重跑结果未知的请求。

达人资料查询首次固定完整排序与本轮资料快照，后续分页复用，后台正常重要度和最近联系更新不会使分页重复、漏人或中断。快照只加密保存在本轮检查点，不发给模型。授权、负责关系、身份、handle 和本轮重要度原消息依据仍实时核验；新增达人在下一次新查询纳入，失去范围或证据失效的旧结果不继续展示。通用达人总结只允许可信页面选择或本轮用户实际点名并查得的子集，不能从宽泛名单自行挑少数人替代完整范围。

`filter_events` 的主题筛选仍只查已有达人事件。业务正文检索另用 `search_chat_history`：按群、时间和一至八个关键词／同义词查询，明确达人时可加达人筛选；每页最多扫描 2,000 条、返回 12 条命中，正文片段最多 480 字。下一页游标绑定查询、范围模式和授权；有游标不能声称已查完，本页命中数不是全库总数。不可读正文、未同步范围和无匹配分开说明，不宣称完整语义搜索。

用户明确“只看重点／常规达人”时，`filter_events.importance` 可在完整报告后筛选，不新增聊天分析。未回复查询的后续筛选沿用本轮重要度快照与顺序，完整卡片和计数一起缩小；“重要的优先”则不使用该筛选。

全量 `summarize_messages` 分页读取时段原消息，由当前助手模型归纳事项，不创建联系人、达人或负责人关系，也不写入固定达人时段报告。每页最多 100 条，每条最多 1,800 字并标记截断；图片等不可读内容保留缺口，不伪造其含义。模型应继续读取到游标为空；达到已有编排上限仍未读完时，必须说明部分总结。没有消息本身不是同步缺口，来源覆盖与实际读取数量分开呈现。旧达人报告不作为全量总结的材料。

回答支持安全的 Markdown 加粗、列表和链接，原文与草稿保持纯文本。资料缺口按原因合并计数，不重复列出相同提示；数量来自截断前的完整结果，小范围缺口显示具体群名。受限模式明确标记为群限制，不提示重复 OAuth。已完成的全历史回填允许历史起点为空，表示不限起点；进行新一轮同步不影响已覆盖历史时段的判断。仍检查实际同步水位、读取权限与正文完整性。读取旧结果时在材料有效的前提下刷新覆盖信息，不重算原回答；描述过时缺口的旧回答不进入新轮上下文。不可读会话最多每 24 小时正常复检一次，恢复成功后自动清除失败状态，不阻塞其他会话、不绕过群限制。

消息原文按当前来源授权重新读取，补引用的原问和有限邻接消息；邻接不是同一事项证明，也不是完整会话。消息引用使用短服务端引用，原始授权快照只在加密检查点保存，不重复发送给模型。指定群的全量总结、消息检索和活动统计实际限制群范围；旧达人事件总结仍按达人范围处理。

达人资料支持多个 handle 与多个正式负责人，维护优先级沿用已有规则，不用 Curva／GMV 推断。群目录包括当前 CM 实际可见的类目群，即使未关联达人或未启用正文同步；群可见不代表有读取正文、发送或 @all 权限。同步查询只读已有状态，不刷新令牌、不触发授权或回填。

活动统计由数据库计算。默认统计全部授权消息，可按英国日期、实际发言人或会话分组；联系人数只认本人私聊、明确 @ 或回复的真实对象，不按群成员推算。达人模式保留原达人发言与明确互动口径。总量与每页分组分开，按达人分组的一条多人消息不能简单相加作为总量。前一时段比较按英国墙钟时长；涉及夏令时重复小时或不存在的钟面时间时，改用实际经过时间并标明口径。它不是寄样、履约或全局唯一未解决事项台账。

回复建议沿用已有取材、筛选、风格和翻译流程，只提供可编辑草稿和中文参考。编辑后中文仍为生成原稿的参考，复制只复制当前正文。生成、编辑和复制不改变事件状态。

## 配置与执行

AI 配置页新增 `operations_assistant`，默认 `gpt-6-luna`，由 Owner 填写独立 Project ID、服务账号 Key 并启用。凭证加密且不回显；编排、临时分析和助手起草均使用本配置，旧总结与其他功能不换 Key。

仅新增 `assistant_sessions`、`assistant_turns` 两表。临时分析复用现有总结和回复任务，以 `origin` 区分，不修改全局设置，不出现在固定时段页面。全量正文与统计只允许本人范围或有效 Owner 跨 CM 查看；达人管理权限、旧达人试点阅读权限不自动扩大为其他员工全部聊天权限。

客户端首次发送前保存会话和请求 UUID；响应丢失时复用两个编号。后台持久执行，刷新和 SSE 重连只恢复进度。收起不停止，停止只影响本轮和专属任务；已提交请求可能计费，迟到回执保留但不展示。

等待子任务时释放 AI 并发名额，完成后按原 call ID 将结果交回模型，不让模型轮询。接现有共享五并发和轮转调度，不增加日 token、TPM 或 RPM 预算。相同工具参数在本轮复用；相同材料的未知调用不自动重发。

已有回答和原文重新打开、进入下一轮上下文时复核权限与材料；撤权或材料变化的旧内容不继续展示。当前会话沿用近期六轮有效上下文，切换对象不携带不兼容资料。正常同步水位推进不当作正文失效。没有新增旧对话列表、找回、跨设备发现或长记忆；已有执行回执与防重复计费机制不删除。正文和工具检查点加密，日志与审计不保存正文或密钥。

失败分为权限变化、资料变化、模型输出格式错误、服务／配额错误和结果未知。正常更新不再误报“AI 返回的结果无法使用”；实际材料失效时清除旧卡片和原文，可继续提新问题，不要求重复登录。检查点记录安全的失败代码、执行阶段和模型轮数，日志只含任务编号与状态，不保存正文或异常全文。

旧版未保存重要度原证据快照的回答，若评估版本已变化，会提示资料变化并要求重新查询，不拿新版本的有效性证明旧结果。新查询不受正常重要度更新影响。恢复页面时，仅隐藏失效旧轮次，保留当前运行请求、停止入口和防重复编号。

按用户指定范围清空助手对话时，只擦除该登录者的提问、工具检查点、回答和会话上下文，旧对话及其原文引用不再可访问。保留请求 ID、响应 ID、用量与清理审计，防止旧客户端重试造成重复费用；不删除 Lark 消息、同步水位、人员或业务关系。清理前备份并等待已发出的请求结束，不新增历史管理界面。

## 接口与实现

| 接口 | 功能 |
|---|---|
| `GET /assistant/scopes` | 本人的有效范围；Owner 返回所有已授权人员供切换 |
| `POST /assistant/turns` | 提交提问，202返回会话与请求引用 |
| `GET /assistant/sessions/{id}` | 恢复本人对话 |
| `GET /assistant/turns/{id}/events` | SSE读取范围、进度、答案和终态 |
| `POST /assistant/turns/{id}/cancel` | 停止本轮 |
| `GET /assistant/evidence/{ref}` | 展开仍有权读取的原文 |

原有工具为 `find_creators`、`summarize_messages`、`filter_events`、`read_event_context`、`draft_reply`；新增 `query_creators`、`list_groups`、`get_sync_status`、`search_chat_history`、`read_message_context`、`activity_stats`。`find_creators` 复用完整达人查询，不再将当前 CM 伪装为唯一负责人。

`query_unreplied_creator_events(start, end)` 不接受模型自选达人 ID、重要度过滤或分页游标。明确点名的独立达人查询仍可先查姓名／handle 后使用通用工具；负责人查询和消息发送权限不因新增工具扩大。全量事件卡片仅由本轮结果自动附出，不把历史查询重新带进无关回答。

Responses 使用严格参数和 `store:false`。最终回答中的 `data_refs` 只能引用已取得且仍有效的查询，服务端生成对应资料卡，不接受模型编造链接、人员或统计。旧最终协议没有 `data_refs` 的已存回答仍可读取。继续使用同一 `operations_assistant` 配置，不增加另一份 Key 或新预算。

实现位于 `backend/app/assistant.py`、`assistant_tools.py`、`assistant_queries.py`、`assistant_search.py`、`assistant_routes.py` 和对应原生 JS／Jinja 组件。继续使用既有 PostgreSQL worker，不新增表、Agent 框架、中间件或向量库。
