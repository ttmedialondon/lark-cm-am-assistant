# 运营对话助手

更新日期：2026-10-13。

## 使用

工作台、我的达人、群发和消息总结页面右下角的“问助手”打开右侧抽屉，可全屏。支持达人资料、群目录、业务消息检索、活动统计和同步状态，原有总结、追问与回复建议继续保留；不发送消息、不修改人员或负责人关系。

Owner 的跨人员测试入口位于“管理台 → 消息内容 → 问助手”；保留单人测试选择，也可直接在问题中点名多位 CM 联合查询，不必反复切换。服务端分别核验目标人员当前正文权限，保留真实来源；普通 CM 仍只查询本人范围。连接失效时单独显示“检查账号连接”，不把群读取限制当作重新授权问题。

## 助手文档库

“管理台 → 助手文档”（`/admin/assistant-rules`，保留原链接）仅向当前有效 Owner 开放。支持新建、编辑 Markdown 文档、草稿／发布／停用，以及全体 CM／仅 Owner 的发布范围。知识文档新建时建议仅向 Owner 发布；范围明确选择全体 CM 后，才供普通 CM 的助手使用。正文加密保存，编辑记录版本和不含正文的审计；并发冲突保留完整草稿，不静默覆盖。文档不存放凭证，不能授予人员权限或新增可执行工具。

内置四份精简公共规则负责权限、问题理解、来源和基础回答协议；业务方法拆为九份处理手册：消息总结、达人未回复、连续跟进、历史检索、达人与群目录、统计比较、回复写作、经营行业分析和连接状态。三份回答模板分别用于事项列表、统计比较和经营报告。可新增任务手册、知识资料和输出模板；四份基础规则的类型、发布状态和全体范围固定。

每次新提问固定当时已发布且可见的文档版本，全文仅保存在加密检查点，不整库发给模型。首请求提供公共规则和名称／用途的短目录，模型按问题调用 `read_documents(document_ids)` 读取相关正文，每次一至三份；读到手册后沿用既有业务工具取材。相似问题复用手册，混合问题可组合，不新增硬编码意图分流或向量库。普通翻译、改写等无需业务资料的问题可直接回答。重复读取同一文档不算新增证据；连续三次无新增材料后结束补查，仍保留任务上限和未知请求不重发。

正文的普通修改不改变正在运行的问题；分段归纳和合并只加载本轮已读的手册／模板，知识正文始终作为事实材料，不作为系统指令。草稿和停用内容不在目录；停止发布、范围收窄或 Owner 撤权后，旧结果和引用也重新校验，不能成为读取私有文档的入口。下一轮重新读取其固定版本，不把历史手册全文带入无关的新问题。

所有长材料分段和合并提供原问题、真实人员和时段，按问题保留进度、收费／佣金、平台反馈或行业线索，不拿待办摘要替代其他分析材料。经营／行业分析未指定时段仍默认近 90 天；普通聊天总结默认今天。知识正文可由 Owner 手动维护，但没有自动文件导入或公网检索；未提供的政策、市场规模和竞争数据不伪装查询。只有实际用于事实判断的知识文档进入 `document_refs`，使用本轮已读取的真实 `doc.*`；处理手册与模板不作为业务事实依据，也不向 CM 展示其正文。知识依据折叠显示标题、版本和正文片段，不冒充原消息来源。

Owner 工具增加 `resolve_staff`，实际业务查询接受可空 `cm_id`；姓名明确匹配后逐人员查询，不通过搜索姓名冒充对方全部聊天。最终页面保留原选中账号，显示实际查询人员；跨人员来源独立翻页，同类来源按实际群和消息 ID 去重。多个 CM 的统计分别展示，不直接相加当作公司去重总量。查询、等待、原文展开、草稿和结果交付均复核当前权限，撤销 Owner 后旧跨人员资料不可继续读取。

## 聊天与查询

CM 默认看到具体事项、已知进度和下一步，不展示首次同步、水位、回填、队列或同步统计表，也不以读取条数作为普通总结的开头；明确要求消息统计时仍提供真实数字。来源按问题需要展示，异常只在“有些内容暂时无法查看”中用业务语言说明，保留实际受限群和不可读附件原因。Owner 在管理员测试入口保留诊断数据，但不因此重复铺出相同业务来源。

业务总结按实际主题生成分类列表，不固定七类或凑空类别。每类展示简短标题、具体事项与进展及必要下一步，来源只绑定支持该类要点的真实消息。模型根据本轮问题返回 `source_mode` 与 `reply_enabled`，不按关键词硬分流、不新增手动开关：

| 问题类型 | 来源展示 | 回复入口 |
|---|---|---|
| 翻译、用户文字改写、文案、一般建议，且不陈述聊天或公司事实 | `hidden`：直接回答 | 不显示 |
| 聊天分类、经营分析、统计或资料概括 | `compact`：末尾一个折叠的“查看依据” | 不显示 |
| 查原话、详查依据、核对付款等具体事项 | `detailed`：逐事项的必要来源和问答 | 不显示 |
| 待回复清单、真实聊天起草 | `detailed`：必要会话和问答 | 按实际回复需求显示 |

`reply_enabled` 只在明确要求回复／起草或待回复清单时开启；检查进度或建议跟进本身不是回复需求，已解决、等待对方及仅内部跟进的事项不自动加按钮。纯知识回答引用实际使用的知识文档，不补虚假消息来源。展开原消息保留群／私聊名、发言人、时间和必要原文，完整原文复用只读 GET，不新增 AI 请求。新提问重新判断展示模式，追问“依据是什么”可沿用真实引用详查，不需要为展开来源重新扫描整库。

分段归纳保存逐事项 `items` 及各自真实引用，合并时保留事项与来源的对应关系；主回答输出 `sections(title, summary, message_refs)`，服务端只接受本轮已取得且当前仍可读的引用，生成来源预览。展示模式不能删除 `message_refs`、`data_refs` 或后台证据来掩盖来源；无论前台是否展开，保存、返回、原文读取与旧对话恢复仍检查权限及资料有效性。模型不提供链接，页面不解析 Markdown 标题来猜来源。来源改变、删除或撤权仍阻止旧材料展示，旧结果没有细粒度引用时不伪造分类来源。

统计、资料和草稿使用各自卡片，不借查询编号伪装原消息来源。没有实际消息引用时，主回答协议强制 `sections=[]`；分类引用只接受消息编号格式，查询编号仅进入 `data_refs`，后端仍逐条验证真实来源。

相关消息变化时，页面清理失效来源和草稿操作，但保留当前对话供继续追问；权限失效、新对话和切换人员仍清理旧会话上下文。

“这些事情的进度怎么样”延续最近有具体事项的那轮，跨英国午夜仍沿用原事项，不把新一天的0条消息当作原事项不存在。已有材料增加或读取情况刷新时，原消息正文和当前权限仍有效的业务事实可保留为历史摘要；失效引用不回放，最新进展重新查询，原文变化、删除或撤权的材料不进入上下文。普通新问题仍按本轮时间理解，不强制沿用旧时段。

“我的达人”每位已分配达人旁可直接询问账号、负责人和维护情况。常用入口为“达人待回复”“今日重点”“帮我回复”，只提交标准业务问题，不附带隐藏的人工筛选。今日重点默认本人聊天。普通入口不显示人员、时间、消息范围下拉框或“修改范围”，也不显示“全部授权消息”等技术标签。聊天先给简短结论，再显示工作清单，不重复整张清单。完整结果保留，默认展开前八项，其余按分组展开。原文与草稿在同一个操作区，手机为单列阅读层。阅读旧内容时不强制滚到底，新结果用按钮提示。手动草稿不被刷新结果覆盖；不新增跨刷新草稿保存、历史管理或长期记忆。

所有提问先交给模型选择工具，不按关键词预先分发。聊天总结、原文检索和消息统计默认覆盖本人的可读群聊、私聊与所有发言人，包括未识别、未分配联系人及机器人消息，不要求对方先成为达人，也不只统计本人发出的消息。只有问题明确要求达人、特定对象或追问这些达人时，才缩小业务范围。查询账号由登录身份固定，伪造其他 CM 参数拒绝；旧达人管理／试点权限不能在运营助手读取其他员工的聊天。有效 Owner 仅在既有管理页面显示跨人员测试选择，普通入口即使是 Owner 也默认本人。本人连接未就绪时提示连接问题，不悄悄回退到 Remi 或其他 CM。管理员切人开启空白会话、清除上一人的卡片和原文，不带入其上下文，也不自动调用模型。姓名重名时列候选，其他正常查询不逐次确认。

时间由问题理解：“今天”是英国当天零点至提问时刻，“昨天”是英国昨天完整一天，“今天上午”默认英国当天 00:00–12:00，实际截止不晚于提问提交时间。普通总结未指定时间时默认今天；用户可直接说“改成上周”。界面仅显示实际查询时段和业务口径，不需要先操作选择器。原时段结论与后来进展分开展示，回复情况与解决状态独立。只有达人事件报告按不超过七天的窗口处理；全消息查询按指定时段完整分页。不宣称跨窗口或跨 CM 的事件已经全局去重。

服务端提供英国日历边界：昨天为昨日零点至今日零点，本周从周一零点开始，不等于滚动七天。本周与上周同期比较分别查询两段真实时间，不把紧挨的等长时段当作上周同星期；夏令时按明确时区偏移处理。

“我负责的达人有哪些未回复事项”使用专用 `query_unreplied_creator_events`，不先让模型分页挑人。默认固定本轮当前 CM 的完整正式负责名单；特定达人问题通过本轮实际姓名／handle 查询确定对象。后台复用现有时段分析，筛选未见已接入 CM/AM 回复的事项，先按达人重要度、再按事项紧急程度排序。重点优先不排除常规达人，未回复也不等于未解决。每项展示达人、群聊／私聊来源和概括，保留原文入口。该结果是已抽取的事项，不是对每条原消息无人回复的绝对证明；不可读附件和同步缺口仍说明。

专用查询最多向编排模型提供 25 项预览和完整匹配数量，后端自动附出本轮全部匹配卡片，不要求模型逐页读名单或输出数百个长引用。部分分析、失效材料或来源缺口不能冒充全范围无未回复事项；原时段以提交时刻为截止，不包含未来回复。完整范围中有多少人负责、实际读到多少消息、匹配多少事项分别计数。当前模式仍可能需要新增该时段的分析任务，不自动重跑结果未知的请求。

达人资料查询首次固定完整排序与本轮资料快照，后续分页复用，后台正常重要度和最近联系更新不会使分页重复、漏人或中断。快照只加密保存在本轮检查点，不发给模型。授权、负责关系、身份、handle 和本轮重要度原消息依据仍实时核验；新增达人在下一次新查询纳入，失去范围或证据失效的旧结果不继续展示。通用达人总结只允许可信页面选择或本轮用户实际点名并查得的子集，不能从宽泛名单自行挑少数人替代完整范围。

`filter_events` 的主题筛选仍只查已有达人事件。业务正文检索另用 `search_chat_history`：按群、时间和一至八个关键词／同义词查询，明确达人时可加达人筛选；每页最多扫描 2,000 条、返回 12 条命中，正文片段最多 480 字。下一页游标绑定查询、范围模式和授权；有游标不能声称已查完，本页命中数不是全库总数。不可读正文、未同步范围和无匹配分开说明，不宣称完整语义搜索。

用户明确“只看重点／常规达人”时，`filter_events.importance` 可在完整报告后筛选，不新增聊天分析。未回复查询的后续筛选沿用本轮重要度快照与顺序，完整卡片和计数一起缩小；“重要的优先”则不使用该筛选。

全量 `summarize_messages` 由系统自动分页读取时段原消息，每页最多 100 条，不要求模型或用户反复请求下一页。可读正文不按展示片段截断；长材料按会话分段归纳，再合并摘要。单条长消息分片保留完整文字和同一个来源引用。分页重复、范围变化、权限撤销或提前结束不能当作完成；结果未知的模型调用不自动重发。该过程不创建联系人、达人或负责人关系，也不写入固定达人报告。图片等不可读内容保留缺口，不伪造其含义。没有消息本身不是同步缺口；读取完当前数据库材料不等于 Lark 已同步全部消息。

新查询完成取材后，以已保存的完整页和消息 ID 固定本轮集合，不因后来新增消息或新发现群重新付费分析。下一次查询纳入新增材料。固定集合仍逐条复核当前权限、删除状态和正文版本；缺页、数量不符、已读正文变化或权限失效仍拒绝。旧任务未保存完成标记时保留原校验，不自动改写其含义。

同一条原消息按真实群及消息 ID 去重展示，不合并不同事项、人员或未知身份的来源。compact 将分类、消息和知识依据放在回答末尾一个折叠入口；统计数值、人员和群目录属于回答内容，继续使用原有结果卡片，不当作原文依据重复折叠。detailed 保留事项相关来源，已在分类中出现的内容不再另铺一遍完整时段卡，仍可翻页查看其余消息。后台完整材料和引用不删减，Owner 与普通 CM 均避免重复业务来源。原文翻页通过独立 GET 接口读取并重新核验权限，不新增 AI 请求或分析任务。普通入口处理时仅显示“正在整理事项”；管理员测试入口保留实际读取与分段进度，不虚构百分比。旧达人报告不作为全量总结材料。

分段归纳与合并使用当前批次的短引用编号，结构化输出只允许选择实际提供的编号；服务端校验后还原原始消息引用。不会模糊猜测引用、丢掉错误引用后照搬结论，或改变原文入口。已发出的旧请求仍按旧编号校验，不重复计费。分析校验、权限变化、资料变化与后台异常分开诊断；诊断只保存错误类型、阶段、代码位置和请求 ID，不保存聊天正文或异常参数。

逐事项归纳与合并允许最多 16,000 个输出 token，主工具循环最多 8,000 个，避免结构化事项和引用被旧 4,000 上限截断；这只是单次容量，仍保留正文长度和引用校验，不新增日用量或速率预算。未完成响应仍拒绝，诊断记录响应状态、截断原因和该次实际用量，不保存部分正文，也不自动重跑未知请求。

单次取材及摘要合并输入最多 64,000 字符，分段概括与逐事项文字合计最多 12,000 字符，适配结构化事项和来源占用；仍不截掉真实原文或删掉错误引用来换取通过。

回答支持安全的 Markdown 加粗、列表和链接，原文与草稿保持纯文本。普通入口将暂不可读内容集中折叠，按实际原因去重并显示已知群名；管理员测试入口保留读取情况和诊断统计。受限模式只有系统确认后才称为群限制，未确定原因则说明暂不可读，不推断用户只授予部分权限。明显影响结论时回答仅补一句具体原因，不反复追加泛化提醒。真正账号连接失效单独提示，不藏入折叠项。已完成的全历史回填允许历史起点为空；新一轮同步不影响已覆盖历史时段。读取旧结果时在材料有效的前提下刷新读取情况，不重算原回答；仍有效的业务事实可用于追问，旧读取诊断不作为当前事实。新增历史记录导致原查询失效时，逐条核验原窗口的授权与正文版本后保留业务摘要、原时段和查询时点，但不恢复旧可执行引用；最新进展需重新查询。不可读会话最多每 24 小时正常复检一次，不绕过群限制。

消息原文按当前来源授权重新读取，补引用的原问和有限邻接消息；邻接不是同一事项证明，也不是完整会话。消息引用使用短服务端引用，原始授权快照只在加密检查点保存，不重复发送给模型。指定群的全量总结、消息检索和活动统计实际限制群范围；旧达人事件总结仍按达人范围处理。

`find_conversations` 按群名、本人可见联系人姓名／别名定位群聊与私聊，不要求联系人是正式达人，也不因匹配到另一员工姓名就切换查询账号。多个重名候选保留供区分；可见会话不保证正文或发送权限。`read_message_context` 默认沿用原时段，`latest` 读取至本轮固定提交时刻的有限后续和引用问答；后续消息有自己的真实引用，不借原问题编号冒充来源。完整时段的进度查询仍需在相关会话内读取请求时段，不能将最新二十条称为全部后续。

达人资料支持多个 handle 与多个正式负责人，维护优先级沿用已有规则，不用 Curva／GMV 推断。群目录包括当前 CM 实际可见的类目群，即使未关联达人或未启用正文同步；群可见不代表有读取正文、发送或 @all 权限。同步查询只读已有状态，不刷新令牌、不触发授权或回填。

活动统计由数据库计算。默认统计本人可读消息，可按英国日期、实际发言人或会话分组；联系人数只认本人私聊、明确 @ 或回复的真实对象，不按群成员推算。达人模式保留原达人发言与明确互动口径。总量与每页分组分开，按达人分组的一条多人消息不能简单相加作为总量。前一时段比较按英国墙钟时长；涉及夏令时重复小时或不存在的钟面时间时，改用实际经过时间并标明口径。它不是寄样、履约或全局唯一未解决事项台账。

## 回复工作区

当前实际时段及业务筛选以只读摘要显示。短追问沿用上一轮实际结果与对象引用：“只看重点”“样品相关”“给第二条写英文回复”分别筛选已有报告或起草；“改成上周”更新时段，“昨天所有聊天”清除旧达人或单群筛选。模型决定复用结果还是新查，不按正则预先分类问题。

分类列表的“第二项／第二类”沿用该轮稳定编号与真实来源，不随新查询排序改变。该类有多个回复对象时先区分实际对象，不任选一人。付款原话查询、事项进度、重点达人未回复、前一时段消息统计和英文回复可组合既有工具完成；聊天中没有确认的到账、发货或履约状态不能当作实际业务完成。

已有分类时，追问上下文只回放已展示的分类、事实和引用，不重复整份底层分段摘要；原始材料仍保存在现有加密检查点供重新查询和核验。来源刷新后的独立历史摘要仍保留，不因精简丢失已核验的业务事实。

分类追问保留真实会话编号；缺少编号时先按消息引用或会话目录定位，不猜群 ID。首次取材前的工具参数错误可纠正后继续；已经读取材料后的来源变化或权限失效仍停止，不丢弃错误编号或扩大范围来绕过校验。

从消息卡片进入回复时，真实事件／消息引用用于定位原文并重新核验身份和权限。普通新问题不附带旧对象、时间或人工消息模式作为强制筛选；后台会话默认只保存当前查询账号，不自动继承旧选择。已有资料按其原业务范围验证，不能因为本轮从达人问题改为全消息问题就丢失合法的历史引用。

清单按“需要我回复”“需要内部跟进”“等待对方”“已解决／无需处理”分组，最后一组默认收起。回复状态与处理状态分别保留在详情里；分组只是当前下一步的展示，不自动结单。新增事件分析给出分组：等对方需要真实 staff 索取资料的依据，不能用没消息推断。历史事件不强制付费重算；缺少新分组时按已有状态保守展示，不将已解决的未回复事项当待办。

新增分析从提供的完整问答中选择同一事项最近一次员工实质回复后的第一条对方消息作为等待起点，并保存实际原文引用，后续催问不重置。历史结果仅按已保存原文计算；不是跨所有历史会话的精确 SLA。明确“今天／明天截止”或带 ISO 日期的截止要求可标记今天截止，只标已知日期，不编造具体钟点，不从普通活动日期猜截止时间；其他地区日期格式未定义时不自动解释。

只有本轮明确需要回复／起草，或待回复清单中的实际回复事项才显示“帮我回复”，不再因有可读文字自动加按钮。用户仍可直接提问为普通聊天、商家、未识别联系人或已解决事项写礼貌回应，不需先建立达人或事件。已有本人风格规则继续复用；带入原问题、引用与有限邻接问答及最新消息，邻接并不自动证明同一事项。

操作区保留对方问题、必要上下文、可编辑正文和中文参考，以及“更短”“更自然”“礼貌催办”“换成英文”。手改英文后可更新中文参考；新材料只提示重新核对，不覆盖手稿。缺少未确认日期或内部进展时，不编事实，可给出带核实提醒的适当措辞；存在实际身份／事项冲突或不可读关键内容时明确指出。无关群的同步缺口不清空当前简单回复。

默认显示目标消息及草稿引用的必要问答；其余候选上下文折叠，全文保留。原文区可独立滚动，不把草稿挤到页面底部。

先提供“复制并打开 Lark”，打开与当前来源相同的会话；不从模糊人名猜会话。复制不等于发送，发送也不等于解决。助手没有直发或修改业务状态工具，生成、改写、翻译和复制均不修改事件、身份或负责人关系。

## 配置与执行

同一次读取复用当前事务内已核验的授权、会话目录和达人名单，不跨请求缓存。全部聊天和普通联系人查询不额外读取达人名单；时段收集只在开始、结束核对全量计数，分段分析只复查本段实际来源，合并和展示仍核验全部引用。复制草稿只核对该草稿，不重读整段对话；有新消息时提醒核对，不覆盖手稿。

AI 配置页新增 `operations_assistant`，默认 `gpt-6-luna`，由 Owner 填写独立 Project ID、服务账号 Key 并启用。凭证加密且不回显；编排、临时分析和助手起草均使用本配置，旧总结与其他功能不换 Key。

沿用 `assistant_sessions`、`assistant_turns` 两表，不为本轮改动新增表。临时达人分析复用现有总结任务，以 `origin` 区分，不修改全局设置，不出现在固定时段页面。新回复在现有助手工具循环中准备材料、保存结构化草稿，检查点加密保存。全消息、达人查询、统计、旧原文和旧草稿统一只允许本人或有效 Owner 读取；助手总结和旧助手回复队列在取材与回存时再次核验，防权限撤销后的子任务或晚到结果继续使用他人消息。固定总结与其他管理页面原有权限不变。

客户端首次发送前保存会话和请求 UUID；响应丢失时复用两个编号。后台持久执行，刷新和 SSE 重连只恢复进度。收起不停止，停止只影响本轮和专属任务；已提交请求可能计费，迟到回执保留但不展示。

等待子任务时释放 AI 并发名额，完成后按原 call ID 将结果交回模型，不让模型轮询。接现有共享五并发和轮转调度，不增加日 token、TPM 或 RPM 预算。相同工具参数在本轮复用；相同材料的未知调用不自动重发。

已有回答和原文重新打开、进入下一轮上下文时复核权限与材料；撤权或材料变化的旧内容不继续展示。当前会话沿用近期六轮有效上下文，切换对象不携带不兼容资料。正常同步水位推进不当作正文失效。没有新增旧对话列表、找回、跨设备发现或长记忆；已有执行回执与防重复计费机制不删除。正文和工具检查点加密，日志与审计不保存正文或密钥。

失败分为权限变化、资料变化、模型输出格式错误、服务／配额错误和结果未知。正常更新不再误报“AI 返回的结果无法使用”；实际材料失效时清除旧卡片和原文，可继续提新问题，不要求重复登录。检查点记录安全的失败代码、执行阶段和模型轮数，日志只含任务编号与状态，不保存正文或异常全文。

旧版未保存重要度原证据快照的回答，若评估版本已变化，会提示资料变化并要求重新查询，不拿新版本的有效性证明旧结果。新查询不受正常重要度更新影响。恢复页面时，仅隐藏失效旧轮次，保留当前运行请求、停止入口和防重复编号。

按用户指定范围清空助手对话时，只擦除该登录者的提问、工具检查点、回答和会话上下文，旧对话及其原文引用不再可访问。保留请求 ID、响应 ID、用量与清理审计，防止旧客户端重试造成重复费用；不删除 Lark 消息、同步水位、人员或业务关系。清理前备份并等待已发出的请求结束，不新增历史管理界面。

## 接口与实现

| 接口 | 功能 |
|---|---|
| `GET /admin/assistant-rules` | Owner 查看目录、编辑文档；`new=1` 创建 |
| `POST /admin/assistant-rules` | Owner 新建或保存文档，CSRF 和版本冲突校验 |
| `GET /assistant/scopes` | 本人的有效范围；Owner 返回所有已授权人员供切换 |
| `POST /assistant/turns` | 提交提问，202返回会话与请求引用 |
| `GET /assistant/sessions/{id}` | 恢复本人对话 |
| `GET /assistant/turns/{id}/events` | SSE读取范围、进度、答案和终态 |
| `POST /assistant/turns/{id}/cancel` | 停止本轮 |
| `GET /assistant/evidence/{ref}` | 展开仍有权读取的原文 |
| `GET /assistant/sources/{ref}?page=N` | 只读翻阅本轮原消息，不调用 AI |
| `GET /assistant/drafts/{ref}/status` | 核对草稿来源与新消息，不调用 AI |

原有业务工具继续复用。`read_documents` 只读取本轮可见文档，不能读取任意文件路径或执行正文。`find_creators` 复用完整达人查询，不将当前 CM 当唯一负责人。Owner 另有 `resolve_staff`，业务查询可指定经服务端核验的 `cm_id`；普通 CM 的业务参数与本人权限保持不变。

`query_unreplied_creator_events(start, end)` 不接受模型自选达人 ID、重要度过滤或分页游标。明确点名的独立达人查询仍可先查姓名／handle 后使用通用工具；负责人查询和消息发送权限不因新增工具扩大。全量事件卡片仅由本轮结果自动附出，不把历史查询重新带进无关回答。

Responses 使用严格参数和 `store:false`。起草先执行 `draft_reply` 取得本人范围内的真实事件／消息材料，再执行 `save_reply_draft` 保存正文、中文和实际原文引用；最后才展示草稿。翻译强制保留用户编辑后的原稿。最终回答中的 `data_refs` 只能引用已取得且仍有效的查询，服务端生成对应资料卡，不接受模型编造链接、人员或统计。旧最终协议没有 `data_refs` 的已存回答仍可读取。继续使用同一 `operations_assistant` 配置，不增加另一份 Key 或新预算。

实现位于 `backend/app/assistant*.py`、`backend/app/assistant_rules/` 和原生 JS／Jinja 组件。沿用 PostgreSQL worker、会话检查点及原规则覆盖表，本轮仅扩展该表的文档元数据，不新增表、Agent 框架、中间件或向量库。通信异常保存安全的异常类型链、请求开始时刻和失败耗时，不记录异常参数、正文或密钥；已发出但结果未知的请求不自动重发。
