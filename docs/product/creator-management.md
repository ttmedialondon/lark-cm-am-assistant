# 人员身份与我的达人

更新：2026-10-15。本文是当前规则；历史 CAP 名单及三阶段扫描记录不代表现行功能。六份后台手册已接入名单导入、新人员自动身份识别和已确认达人的账号补配，见 [达人识别流程](../specs/creator-recognition-workflow_v1.0.md)。负责人匹配另用三份处理手册，分别规定关系判断、取材交接与自动关联。复用现有队列、凭证和人工事实，不全量重扫存量联系人。

## 1. 人员、账号与负责人

- 人员身份、TikTok handle、CM/AM 负责人、群用途分别管理，不互相推导或覆盖。CAP/非 CAP 已取消。
- 达人按联系人 ID 去重，不按姓名合并；同一人可有多个 handle、多个负责人。同一账号涉及其他人的正式关系时保留冲突，不自动转移账号或合并人员。
- 负责人候选仅为“人员”页面已接入且有效的 CM/AM。识别或上传操作本身不产生负责人；有效名单、人工确认，或通过当前负责人匹配规则的结果，才建立正式关系。
- 人工确认和人工导入数据保留。新表缺少旧账号，不删除原关系。
- 普通 CM 使用本人范围；Owner 或获准的达人管理人员可跨 CM 管理。关联达人不增加聊天读取权限。

## 2. 当前入口

“我的达人”默认显示正式名单；Owner 可切换“未分配达人”，不再有独立候选达人页面。姓名进入有权限的个人资料，旁边的小图标打开 Lark 私聊，不发送消息。

名单按人展示全部已关联账号，可按维护优先级排序、筛选。优先级分为重点、优先、常规、久未联系、待评估；基于本人授权聊天，不依赖 Curva 或 GMV，并随新资料和时间变化。Owner 可手动调整优先级、修改账号；人工调整优先，不展示冗长分析依据。

## 3. 名单导入

选择负责人 → 上传单列 handle Excel → 检查预览 → 确认导入 → 后台找相关群或私聊、找真实人员 → 分别核验身份与账号，满足证据及配置阈值则入库，其余人工核对。

每行一个账号，去重后独立处理；上传者与所选负责人分别记录。导入机制不再要求 CAP 或 Curva 收录，不创建空壳联系人。多群成员按稳定联系人合并；相似群名、同名人员、共享群不能单独证明账号归属。只有完整成员与对应群证据支持唯一人选时，才可判断没有发言的成员。

取材限于所选 CM 当前可读范围。每轮最多准备 100 行，共用一次群目录和历史搜索，逐行保存加密材料；大名单分轮处理，让其他功能继续准备。规范合作群名精确且无歧义时本地完成会话定位，不再付费找群，但人员身份和账号归属仍需核验。其他候选会话和人员核验使用导入配置中的自动确认阈值，保留完整问答、引用、覆盖缺口和实际用量；候选会话结论不成立时，不继续付费猜人。新身份至少满足 95% 门槛；已确认身份直接复用，账号独立判断。请求前后检查当前权限、实际材料引用及相关人员变化，不因无关新消息重建整批历史。配置阈值在请求途中变化会使旧结果失效，不自动放宽已付费结果。

在“导入记录”中打开批次的“核对账号”，每页显示 25 条未入库账号（含暂缓记录）。逐行展开后可按需查看判断、引用原文及更多上下文，修改 handle、搜索所选 CM 当前可访问的 Lark 用户，再确认入库或暂缓。保存一行不会清空其他行未保存的输入；审核期间暂停列表自动刷新。人工确认仍检查当前访问权限、已有账号关系及人员身份冲突。确认登录或权限失效后，立即清空该页原文与草稿、关闭弹窗，迟到响应不能恢复内容；普通校验或网络失败保留编辑。

## 4. 已确认达人的自动匹配

新人员身份识别复用“达人识别与账号匹配”的开关、凭证和队列，仅处理上线后新发现人员或实际新消息、编辑、相关群名变化，不因历史回填批量扫描。本人业务证据及至少 95% 门槛通过后自动确认；没有账号或负责人也可先确认身份，不默认归给发现者。没有可读文字时等待新材料，人工身份、拒绝和已有关系不能被覆盖。

- **Handle 匹配**：从群名、本人发言、完整问答和账号链接召回候选，再核对本人关系。Curva 只是辅助目录；未收录不否决明确账号。默认跳过同一人已正式关联的账号，但仍寻找其新账号；主动复核或实际冲突时才重查旧关系。规则见 [账号协议](../specs/creator-handle-association-prompt_v1.2.md) 与 [队列方案](../specs/creator-handle-matching-queue-plan_v1.0.md)。
- **负责人匹配**：新 CM 接入、相关新消息或材料变化后，自动唤醒受影响达人的负责人任务；没有新材料不重复调用。一次请求同时读取后台文档库的《达人与负责人关系判断》《负责人取材与交接判断》《负责人关联与案例》，不是为每份手册另调一次模型。依据已接入 CM/AM 的真实业务责任，达到配置阈值且证据有效时自动新增；保留多位负责人，不覆盖已有关系、不自动恢复人工解除。编辑手册不改现有确认关系，也不全量重跑。规则与执行边界见 [负责人匹配](../specs/creator-responsibility-matching_v1.0.md)。
- **群用途分类**：客服、机构达人、培训、类目、活动；不足时未确认。共享群只处理一次，达标自动入库，人工分类优先；详情显示分类角标。规则见 [群分类](../specs/creator-group-classification-prompt_v1.1.md)。
- **维护优先级**：模型提取聊天事实，后端结合近期互动和时间分档；每位 CM 的依据独立，不因共用达人而共享聊天。规则见 [事实提取协议](../specs/creator-importance-facts-prompt_v1.0.md)。

各功能独立配置和持久化队列，后台任务公平轮转使用 5 个请求名额；运营助手与主动回复另有 2 个交互名额，桌面主动请求和群发发送仍独立。同一 OpenAI 项目的真实限流与欠费暂停共用。开关以线上为准，代码发布不自动开启、重扫或改变阈值。

相同材料复用结果；授权、正文、群名、身份或配置变化使受影响材料失效。明确可重试的失败有限重试；请求结果未知保留回执，等待人工核实，不自动重复付费。正式写入前核对当前授权、引用、版本及冲突。

## 5. 下游与退役边界

正式确认身份或新增有效负责人关系，会登记最近七个英国日期的消息总结补算信号；需功能已启用、已有负责人且消息当前可读。已有账号或群分类不是总结前提。规则见 [消息总结](message-summary.md)。

群分类用于群发选择，不直接触发发送；客服群按人匹配，其他类别按本人可见群选择。名单、模板、确认和回执规则见 [部署手册](../runbooks/deploy-mvp.md#群发页面与正式发送)。

### 手动维护账号

“我的达人”每行的“管理账号”支持添加、替换和解除本人负责达人的账号，保留其他 handle、全部负责人及历史。顶部“手动关联”按 handle 搜索本人可见的 Lark 用户，选择实际人员 ID 后确认“关联并加入我的达人”；已有其他负责人不覆盖。本人导入的待核对账号继续在导入记录中处理。

账号已正式绑定其他人员时，CM 不能抢占；Owner 可从原人员“更正 Lark 用户”显式迁移账号关系，不迁移聊天或负责人。所有修改有人工确认人与审计，错误旧关系留下拒绝记录，避免 AI 重新恢复。保存后列表、搜索和群发使用新关系；旧名单重新核验，已冻结发送不因 handle 改动换收件人。当前仍限制一个 handle 一个正式联系人，不支持共享账号或人员合并。

旧联系人泛扫身份、旧负责人扫描、从人员反查 handle 及“身份 → 负责人 → handle”流程已退役；旧入口不能执行或确认。历史任务、密文域、来源引用和正式关系保留，不重放历史清理迁移。当前负责人只读人级关系；旧账号级表不再参与名单、冲突或调度，已结束记录仅供解除历史核对及审计。
