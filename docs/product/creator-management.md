# 人员身份与我的达人

更新：2026-09-14。两条入口：AI 从人员出发判断身份、负责人和账号；Excel 从一位 CM 提供的 handle 名单出发找人。旧工程不恢复；只有信息及关联完成后才进入“我的达人”。

## 现在先做：把所有人认清楚

入口是后台 **人员目录**（`/admin/contacts`），不是前台达人名单。

```text
全部在库人员
    ↓ 按同一个联系人去重，不按 CM 重复扫描
从本人可读取的历史发言中挑选重要片段
    ↓ OpenAI 判断一个主要身份
六类之一 ／ 待识别
```

| 类别 | 主要看本人说了什么 |
|---|---|
| 达人 | 本人实际做直播、短视频、带货或内容合作；替别人协调不算本人是达人 |
| 其他机构负责人 | 代表其他机构管理、对接或安排达人；不把所有服务商都算机构负责人 |
| 同事 | 明确为本公司工作；已核实的内部租户事实可以直接保留，不重复付费猜测 |
| 商家 | 代表品牌、店铺或商品供应方开展业务 |
| 字节官方 | 明确代表字节／TikTok 官方处理业务；只是讨论 TikTok 不算官方人员 |
| 其他人员 | 有足够材料确认其身份不属于以上类别；不是信息不足的兜底 |

只允许一个主要类别。低于 **0.95**、证据冲突或信息不足，统一 **待识别**。没有可读发言、只有寒暄或无法提取文字，也显示待识别及原因，不发送空材料给 API。阈值是保守的产品门槛，不是保证 95% 准确；结构化输出仍可能出错。[OpenAI Docs](https://developers.openai.com/api/docs/guides/structured-outputs)。

历史不限定最近多少天；本人重要发言和分散时间的片段结合选取。业务词只帮助找材料，不直接决定类别。昵称、handle、群名不能代替本人业务证据；不需要先找到 CM 对话，也不要求 handle 齐全。不会把同群其他人的整段聊天传给模型。

执行复用现有 OpenAI 配置及队列：每人最多 **16 条本人片段、8,000 正文字符**，全局最多 **3 路并行**，每个任务最多 **2 次尝试**。尝试计数包含领取后检查，不等于付费调用次数。同一规则版本自动处理每人一次，刷新页面不重发请求；新入库人员在开关启用时补入队列，异常明确留在目录，不无限循环。

保存并开启“全员身份识别”后开始；关闭保留排队任务，停止新领取并取消在途任务，迟到结果不再写入。重新开启会继续排队任务；被取消或需要补材料的人可由主人在详情点“继续识别”，沿用剩余尝试，不清零预算。密钥留空不覆盖已有密钥。

人工已确认身份优先，其次是已核实内部同事，最后才是新 AI 分类。重判只替换旧 AI 分类，不覆盖人工、租户原始事实、权限、账号或 CM 归属。旧 AI 结果保留为历史记录，不当作本轮结论。发送前和保存前都检查授权、作者和原文是否仍有效；正文不进普通日志。

目录保留类别、姓名搜索、识别进度和人员列表；开启／关闭和人工确认仍由系统主人操作，不扩大聊天权限。

## 第二步：达人归属判断

临时入口在后台 **AI 功能 → 达人归属判断**（`/admin/ai/creator-ownership`）。

**选 CM → 预筛选 → 点击开始分析 → 建议关联的进入候选 → 第三步找 handle。**

默认 Remi（Quanzhen Liang），也能选择其他有效正文授权的负责人。始终用稳定用户 ID 关联，不按姓名猜测。只取人员目录当前有效分类为“达人”、有 Lark 用户且没有有效负责人的人；已有的人级归属或旧账号名单仍有负责人时都排除。结束的历史关系不阻止扫描。一人多个 handle 也只判断一次。

### 先在本地筛选，不调用 AI

| 材料情况 | 处理 |
|---|---|
| 所选 CM 没有可读材料 | 暂不分析：无可读材料 |
| 只是同群，没有直接交流线索 | 暂不分析：未找到直接交流 |
| 只有问好、表情、感谢、系统消息或广播 | 暂不分析：缺少业务内容 |
| 只有单方业务发言，没有回应或明确负责说明 | 暂不分析：双方材料不足 |
| 相同人、CM、规则、模型和材料已经成功分析 | 复用结果，不重复请求 |
| 完整有效对话本身超过材料上限 | 暂不分析，不裁掉可能改变意思的句子 |

普通情况至少双方各一条实质消息并涉及业务，不硬设“必须十条”。少量消息明确说明接手、负责或交接时可送 AI 核实。暂不分析不等于不属于该 CM；预筛选规则要抽样检查是否漏人。

### 每次只看一位达人与一位 CM

只读取所选 CM 当前有效授权观察到的材料，不复用第一步跨 CM 汇集发言的取材范围。结合相关私聊、群内双方回复/@和必要上下文，单纯同群、时间相近不算实际业务往返。没有回复标记的连续群聊，只在双方有具体共同话题及回应线索时作为弱材料。

历史不限最近多少天。兼顾最早、最新以及交接、代班、终止合作等反向材料。每对人最多 **6 段、40 条消息、16,000 个正文字符**；保留完整交流，不把整个 CM 的消息上传。如果反向段无法完整装入，整个人暂不分析，不能只保留旧正向材料。缺失历史、媒体文字或对话关系时不得猜测。

### AI 的三个结果

| 结果 | 规则 |
|---|---|
| 建议关联 | 有持续实际对接或明确负责说明；至少 0.95，引用有效，没有未解决的冲突或缺项 |
| 待确认 | 有业务合作，但不足以确认当前负责关系；没有材料不能当反向证据 |
| 不建议关联 | 有明确反向证据，例如交接、临时帮忙或已经结束；不能顺手归给其他 CM |

一次样品处理、有私聊、回复多、群名、handle 或 CAP 身份都不能单独证明负责人。高可信的“持续对接”至少引用两个跨日双向业务回合；“明确负责”须实际引用该 CM 对这个达人的负责说明，不能借用材料中另一条未引用消息。反向结论也要有真正反向原句支撑。旧合作不自动失效，但也不自动证明当前仍由该 CM 负责。0.95 是产品门槛，不是准确率承诺。

“负责”指实际业务对接，不要求合同、正式任命或“我是你负责人”原话。要分清 CM 临时帮助别人，和 CM 自己休假让同事短时代班；若原 CM 后来继续对接，不能只凭已结束的代班认定交接。退出机构/CAP 也不等于停止非 CAP 业务合作。抽样限制、关键词标记只是选材提示，不是已发生交接的证据，不能凭提示编造冲突。结论置信度表示对本条判断的把握，不是归属概率。

模型返回固定结论、分数、简短说明、引用、冲突和缺项；使用现有 Responses 接口的严格结构化输出，服务器核验引用与业务门槛，不把格式正确当作事实正确。[OpenAI 官方文档](https://developers.openai.com/api/docs/guides/structured-outputs)

### 候选与运行

- 仅主人可预筛选、开始、暂停、继续或暂缓；获准查看 AI 页面者只读，第二步原文证据仅主人可看。不恢复旧测试编辑特权。
- **只有当前有效“建议关联”进入该 CM 候选库**。第二步“待确认”和“不建议关联”留在后台，不删除、不混进 CM 候选。
- 第二步不写正式负责人。原来的直接确认及批量确认入口关闭，不能绕过 handle 核实。已有负责人不可抢占。
- 先分析约 20 人，优先覆盖私聊、群聊、少消息和交接；核对后再点“分析剩余”。没有可用样本的类别不伪造覆盖。
- 预筛选由一个后台线程处理，不阻塞聊天同步，也不占 OpenAI 槽。付费分析与现有 AI 功能共用最多 **3 路**。
- 开始按钮只校验引用并排队，完整历史复核在后台发送 API 前执行，避免批量点击长时间卡住。预筛选进度、判断结果和实际请求数分别显示。
- 每人通常一次请求；明确可重试的限流最多再试一次。网络结果不明或进程中断，不自动重发可能已付费的请求。
- 刷新只读状态。暂停后不登记新请求，已经开始的少量请求允许收尾；暂停不会撤销已消耗的用量。
- 判断规则升级后另建批次，旧结果保留供历史查看，不能直接确认或混用缓存。
- 发送前、结果保存前、确认前检查人员、负责人、授权和原文。引用被冻结且绑定所选 CM；新增相关对话、交接、编辑或撤权会让旧材料失效，无关会话不影响。
- 页面分别显示待分析、排队、分析中、完成、跳过、异常，以及已发起请求和 token 用量；本地处理人数不能冒充 API 调用数。
- 列表轮询分页并只核验所引用消息的当前阅读权限与内容，不重扫全部历史；完整历史是否有新进展，在打开原文、发送、保存和确认时检查。列表中的历史 AI 建议不保证当前仍可确认。

这一步不重新判断身份，也不猜 handle。账号核实交给下述第三步；Excel 是文末独立入口，不经过第二步。协作 CM、多负责人、自动交接、消息回复或总结不在本次范围。

## 第三步：找 handle，完成入库

前台入口 **我的达人**（`/creators`），分“候选达人”和“我的达人”。CM 只处理自己的候选；主人可以选择 CM、管理扫描和自动入库开关。无需给 CM 后台权限。

点击候选、正式名单、后台达人目录或归属判断中的达人姓名，可在新标签页唤起 Lark 私聊；原有“查看”仍打开本站人员详情。链接只使用该行保存的用户 `open_id`，不按姓名、handle 猜人，缺少有效用户时不提供跳转。无需请求新权限，不调用发消息接口、不预填或发送消息，也不改变归属。

**打开的是当前 Lark 登录账号与达人的私聊，不是所选 CM 的历史会话。** 例如 Shuxuan 查看 Remi 名单，点击后仍按 Shuxuan 当前的 Lark 账号打开。官方只保证打开当前用户可访问的已有会话，未聊过或无访问权限时不保证成功，也不自动代建会话；浏览器可能提示“打开 Lark”。[Lark 官方 AppLink](https://open.larksuite.com/document/common-capabilities/applink-protocol/supported-protocol/open-a-chat-page)

```text
第二步建议关联 → 该 CM 的候选达人（还不是正式归属）
                       ↓ 本地挑选群名和相关历史片段
                  OpenAI 判断账号属于谁
                       ↓
        handle 明确、本人绑定可靠、无冲突？
             ├─ 是 → 自动开关开启后 → 我的达人
             └─ 否 → 留在候选 → CM 补填或改正 → 确认入库
```

### handle 从哪里找

- 优先取相关群名，例如 `jennie_daily*Trutonic Media`、`jennie_daily。cm1`、`jennie_daily X TT`；只去掉明确的装饰和机构后缀，保留 handle 的点、下划线和数字。
- 再看该 CM 可读历史中双方的账号自述、TikTok 主页/视频链接和本人视频、直播、广告码等账号业务。历史不限近期；每人最多 20 个相关群名、40 条消息、16,000 正文字符，不把整个 CM 的聊天上传。
- 群里的通用品牌广播、`@all` 不当账号线索；CM 消息必须与该达人有明确交流关系。广告授权码只保留“已提供”的标记，不将可使用的原码交给模型。
- AI 只能选择原材料确实出现的 handle，必须引用材料；不能从姓名、读音或“意思相似”编一个。没有线索就不调用 API，保留候选，handle 显示 `—`。

### 什么情况下自动入库

以下条件适用于从人员出发的 AI 入口；Excel 导入按文末的群内达人人数规则处理。以下条件必须同时成立：

1. 仍是第一步有效达人，稳定 Lark 用户明确，第二步仍建议归给这位 CM。
2. handle 完整，AI 对“这个账号属于这个人”的置信度至少 **0.95**，并有可验证的账号本人关系。
3. 本人明确说明账号，或者“群名 handle + CM 向此人发起具体账号业务 + 此人以本人视频/直播/广告码等回应”形成明确对应。
4. 没有未解决的其他账号主体、改名/旧号、负责人或已有账号冲突；材料和授权仍有效。
5. 主人已开启该批次自动入库。默认关闭，先预览、抽查再开启；暂停批次也暂停自动入库。

**同一个群、只发现一个已分类达人、只 @ 一次、一次寄样或模型给高分，都不够。** 截取后仍缺关键材料时保守留给 CM。0.95 是门槛，不是准确率保证。

### CM 怎么处理剩下的

- 单一猜测预填，可直接修改；多个可能账号列选项，不默认全选。
- 没找到就显示 `—` 和输入框。CM 确认准确 handle 后可以入库，不要求人工填写再达到 AI 高分。
- 同一个人确实有多个账号，可以逐个确认，但“我的达人”只算一个人。
- CAP 属性默认待定，在“我的达人”按人选择 CAP、非 CAP 或待定。若 Lark 用户或负责人错了，不能只改一格继承旧判断，应回到第二步重新核对；当前页面不提供绕过第二步换人的入口。
- 可以暂缓。账号已属于别人、人员已有负责人等冲突必须另行核实，不能覆盖已有记录。

确认通过后，在一个事务里同时保存“用户—账号”和“用户—CM”；任何一步失败都不留半成品。自动与人工确认分别记录来源和操作者，不把 AI 写入伪装成人工操作。

### 执行边界

免费取材不占 API 槽，明确点击开始才付费；第三步与其他 AI 共用全局最多 3 路并行。刷新、预览、重复点击不重复发起同一任务；同规则、配置和材料的成功结果可复用。每人最多两次尝试，结果不明的付费中断不盲目重发。

已经分析过但材料发生变化时，系统主人可以单条「更新材料」，再点开始分析。必须先关闭自动入库、等当前批次结束，并且还有剩余尝试次数；材料没变就不重测。上次结果、来源和用量加密保留，不重置累计费用，也不因修改校验代码直接把旧的待确认结果升为正式。

“同步候选”可以重新整理尚未付费、尚未确认的材料；已经付费的结果不会因此被清空或重发。分析中和暂停中的批次不替换材料。

入库前再次检查第二步结论、账号冲突、消息授权、群名及成员快照和相关历史。页面只做引用级轻量校验，失去阅读依据的 AI 选项不再展示。已存在的正式名单继续显示，旧数据不重写；本次不启动消息总结或自动回复。

## Excel 入口：一份名单，一位 CM

**每行一个 handle，整份表属于一位 CM。名单中的账号都是已确认的达人账号；系统负责找到对应的 Lark 用户。**

现在由主人选择 Remi 后代传；CM 自己上传时固定为本人。上传人和负责人分开记录。只接受 `.xlsx` 单列，表头 `handle` 可有可无；可填 `@账号`、纯 handle 或 TikTok 主页链接。保留点、下划线和数字，统一大小写并去重，不猜测拼写。预览列出无效行。

```text
选择 CM 和名单属性 → 上传单列 handle 表 → 核对预览 → 确认导入并匹配
                                       ↓
                       找到该 CM 可访问的账号对应群
                                       ↓
                     合并各群成员，按 Lark 联系人去重
                                       ↓
                  复用有效身份；需要时由 AI 识别群内达人
                      ├─ 唯一达人、无冲突 → 绑定 handle，入库
                      └─ 零位／多位达人 → 保留 handle，用户留空待核对
```

### 名单决定负责人和 CAP 属性

- 整份表指定一位 CM，AI 不再判断这些账号是否由该 CM 负责。
- 上传时明确名单属性，默认 CAP，也可选非 CAP。入库后应用到对应达人，同一人多个 handle 共用一个属性；不从账号拼写或 Excel 标签推断属性。
- 未找到唯一用户时，CAP 名单的账号候选仍显示 CAP；“待核对”指用户匹配状态，不会把 CAP 改成待定。
- 已有相反 CAP 属性、人工确认的非达人身份、账号主人或其他负责人冲突时单独处理，不自动覆盖。

### 按群里的达人人数匹配

先查已有正式账号关联。同一账号已经在这位 CM 名下，就复用，不重复建人或调用 AI。新匹配先找群名中的精确账号，例如 `handle X TT`、`handle。cm1`、`handle * Trutonic Media`。只有相似拼写，不能直接认定为对应群。

一个 handle 对应多个群时，合并各群可识别的成员，再按稳定联系人 ID 去重。同一个人在多个群出现仍算一人，不能只挑第一个群。复用人员目录当前有效的达人和非达人分类；需要补充判断时，AI 只识别群内哪些人是达人，排除同事、机器人、商家等。

| 去重后的识别结果 | 处理 |
|---|---|
| 只有一位达人 | 将该用户与 handle 匹配；无已有归属或人员冲突就自动入库 |
| 没有识别到达人 | 用户置空，保留 handle 和名单属性，待 CM 核对 |
| 有两位或更多达人 | 用户置空，说明识别到多位达人，待 CM 核对 |
| 没找到对应群或材料无法使用 | 保留账号候选并说明原因，不创建空联系人 |

唯一已识别达人无需发过言，也不要求提到 handle、提供广告码或达到“账号归属 0.95”评分。身份识别与账号匹配是两件事：模型需要认出达人，但不再额外证明这位达人说过什么才能绑定账号。

只读取所选 CM 当前可访问的群和成员。需要 AI 时，只发送相关群和必要的人员发言，不发送 Remi 的全部聊天，不强制有私聊。成员、授权或人员分类变化后，入库前重新检查；不以截断后的部分成员名单宣称只有一位达人。

### CM 怎样处理剩下的

入口仍在 **我的达人 → 候选达人**，Excel 与 AI 候选合并展示，来源分别为 Excel、AI 或 Excel + AI。来源表示实际使用的材料或结果，不代表已经通过入库条件；复用已有身份不冒充新一次 AI 调用。

用户缺失或多人不明确时显示 `—`，handle 和名单属性保留。CM 可以修改 handle、搜索当前可访问的用户，选定正确的人后点击“确认入库”，不需再确认负责人。修改账号或用户会让原匹配判断失效，并重新检查账号、用户、属性和负责人冲突。不确定的可暂缓。

正在运行的结果不能覆盖人工改动。同一达人确认多个 handle 后合并到同一个人。正式名单按人计数，导入进度按账号行计数。

### 执行和数据保护

检查表格与刷新不调用 AI。确认导入后，系统先整理对应群和有效身份；本地已有唯一达人时可以直接匹配。确实需要识别人员时才发起 AI 请求，与其他 AI 共用最多 3 路并行；支持暂停、继续，限流最多两次尝试，付费结果不明的中断不自动重发。

导入只追加或合并，不因新表少了某个账号删除已有达人。不解析旧大表、多工作表或 CM／TAP CM 列，旧大表的数量和匹配率不作为新表结果。

本次规则替换旧的账号归属评分、本人账号声明和广告码关系校验；旧判断不当作新规则的识别结果。重新处理未确认账号时保留原始加密材料、结果和累计用量，已有正式达人及人工改动保留。
