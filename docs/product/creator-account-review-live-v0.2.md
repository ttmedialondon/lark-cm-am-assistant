# Remi 真实账号核对页 v0.2

日期：2026-09-08。用于 Shuxuan Li 和 Shang Ma 核对需求；替代原假数据界面，不是正式账号确认系统。

## 本次交付

- 地址沿用 `/dashboard/creator-setup-preview`，前台入口改为“Remi 的达人账号核对”。
- 读取服务器已归档的 Remi 来源名单，核验快照完整性，并逐项复核当前联系人、角色及负责人绑定。固定 Remi 账号，不接受客户端换负责人。
- 一行一个来源 handle，保留 Excel 行、CM/TAP CM 原值、原群名、联系人对应状态和资料缺口；同一联系人多个 handle 不合并成一行。
- 首屏只读取名单元数据。点击有效正式映射后查询该联系人的相关会话；再点击会话才分页读取正文。
- 群聊和单聊来自当前有效授权、可见、启用同步的相关会话，可能包含其他 CM 的授权来源，明确标出来源；不是“只有 Remi 的单聊”，也不是账号已经确认的工作群列表。
- 移除演示保存、自动认领和会话确认控件。不向浏览器存储写入真实名单或聊天，不提供业务写接口。
- 业务数据只读；沿用登录会话活动记录，显式查看正文仍记录安全阅读审计，审计失败不返回正文。

## 当前数据与缺口

上线前服务器检查：来源名单 143 个账号；正式库 115 位联系人、117 个 handle。名单来源为 2026-09-07 的整理快照，页面显示整理时间；不是重新扫描整个 Excel 或重做身份判断。

| 分类 | 账号数 | 页面解释与操作边界 |
|---|---:|---|
| 依据已归档 | 64 | 表示依据字段可追溯，不是准确率，也不代表 CM 已在新流程确认 |
| 依据未完整归档 | 50 | 保留既有正式映射，显示待补原因；不是直接认定匹配错误 |
| 联系人尚未确定 | 24 | 保留来源账号，不伪造联系人或会话入口 |
| 别名候选 | 2 | 显示候选身份，不能据此开放候选联系人的聊天或当作正式账号关联 |
| 历史映射待确认 | 3 | 标明风险；可查已有正式联系人的授权会话，不能据聊天自动认可 handle 对应 |

上述计数是检查时快照，运行页面以实时校验结果为准。快照缺失、校验失败或不是 Remi 时显示缺口，不回退假数据。绑定已变化的项目转为待核对并关闭会话入口。若正式库出现快照未包含的 handle，显示额外缺口数量，不静默新增来源行。

核心业务缺口：

1. 当前正式归属仍是“联系人 → CM”，没有独立的“社媒账号 → CM 确认”记录。因此已有正式关联不等于 Remi 已确认本次账号设置。
2. 尚无正式“账号 → 会话选择”关系表。当前会话依据精确联系人身份关联，仅供人工查看；群名、同群、相似 handle 和私聊均不自动成为已确认关系。
3. Excel 原群名只是来源文本，未持久绑定真实 chat_id，不能按同名直接生成已选群。
4. 未找到相关会话可能是未同步、授权失效或身份链缺失；不能据此断言从未沟通，也不阻止未来账号单独入库。
5. 本轮没有上传新 Excel、补写别名、重新分配负责人或恢复 AI。以上缺口应由后续明确的账号模型与人工确认流程解决。

## 安全边界

- Shuxuan Li：固定授权 UUID、active 且当前有效 owner。
- Shang Ma：固定授权 UUID、active 且仍拥有现有 `creator-review` 读取权限。此次不新增后台权限；撤权后真实页立即不可继续读取。
- 其他账号不显示入口，直接访问也拒绝；显示姓名不作为授权依据。
- 会话及正文查询在 SQL 层重新验证正式达人角色、当前 Remi 负责关系和来源同意。请求任意联系人、另一个负责人的账号、无效/失效会话均不能越界。
- 正文继续采用既有纯文本渲染、常见邮箱/电话号码遮盖与分页规则；不下载附件、不跟随正文引用读取别的会话。
- 页面不缓存、不嵌入全量正文、不写浏览器存储、不改变同步开关。正式达人角色、负责关系、后台权限和 AI 配置应与发布前一致。

## 验收

- 两个指定账号看到相同的 Remi 名单和缺口，查看人身份与数据负责人明确分开。
- 可按 handle、联系人、来源群名搜索，可按依据分类、未定位、别名、历史映射和已变化状态筛选。
- 名单加载不读取正文；有效联系人详情只加载授权会话元数据；正文点击后读取并审计。
- 未定、候选或失效映射不开放聊天；已有归属变更和来源撤权在下一次读取生效。
- 正文转义、安全分页和只读限制经过测试；没有伪造的置信度、已选群、CM 确认结果。

后续待用户核对布局和实际案例后，再实现账号实体、CM 首次确认、账号—会话关联、交接及增量维护。不要将此只读核对页误当作这些流程已经完成。
