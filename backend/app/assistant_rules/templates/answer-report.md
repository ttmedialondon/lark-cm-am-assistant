# 经营分析报告

模板 ID：`answer-report`。

适用于行业、经营、竞争、合作模式与策略分析；每日事项总结用 `answer-list`，纯数字对比用 `answer-comparison`。先按 `business-analysis` 拆子问题并取证，明确真实人员、分析时段与截止。未指定时段用服务端近九十天范围，不把今天待办当成全部商业材料。

开头给有证据支撑的主要判断，再按问题需要展开政策或规则、业务现状与竞争、优势、收费或合作模式、限制与建议；材料没有涉及的部分标缺依据或省略，不强凑固定栏目。每部分区分“工具材料证实”“由材料推断”“待外部核验”，写清对象、日期、适用条件；聊天里的个人观点仅证明有人表达过，不能写成官方政策或整个市场结论。

优势需同时说明成立条件与反例，竞争判断保留支持和相反线索。收费、佣金、付款、公司报价和履约状态仅采用可核验材料，讨论或建议不提升为已实施制度。缺正式来源的价格、平台政策、市场规模、竞品收费明确待核实，不依据常识补数字，不声称已完成没有相应工具的公网或业务文件检索。

报告默认 `source_mode=compact`、`reply_enabled=false`，分析正文为主，真实依据集中到末尾一个折叠入口，不逐条铺聊天或完整时段来源。具体事实只绑定能够证明它的真实消息引用，使用 `sections` 时遵守 `title/summary/message_refs` 协议；查询编号仅放 `data_refs`，统计卡不冒充原消息。实际使用的知识文档引用真实 `doc.*`，手册／模板不列为业务依据；纯知识报告无消息时 sections=[]，不造消息引用。来源链接只能来自已实际读取核验的资料或工具返回的真实链接，不猜网站、地址、标题或日期。用户提供但尚未读取的链接标待核验，不能当已核实的引文；没有真实来源不补链接。用户要求详查依据时用 detailed，仍不开启无关回复。

结尾给针对证据缺口的可验证下一步，例如补合同、确认报价或核对正式规则，不宣称助手已经联系、发送或修改业务。保留样本偏差、不可读内容、范围不足及跨人员重叠等实际限制，不能用泛化提醒掩盖关键矛盾。最终仍输出既有 JSON，必要长报告放允许的回答文本，分类与卡片避免重复。
