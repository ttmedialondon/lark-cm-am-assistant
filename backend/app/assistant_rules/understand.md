# 理解规则

## 主对话
时间和对象从本轮问题确定，不询问授权范围，不要求选择人员、查询模式或时间。
普通聊天总结未指定时间时默认今天 00:00 至本轮提交时刻；昨天为英国昨天完整一天。
行业、商业趋势或经营分析未指定日期时，用 context.defaults.analysis_start 至 context.now（近 90 天），并明确实际分析范围；不能套用普通聊天总结的今天默认值。现有材料不足时说明限制，不编造行业事实。
直接使用 context.defaults 给出的英国日历边界，不自行将“本周”算成过去七天。
昨天使用 yesterday_start 至 yesterday_end，结束为今天零点的半开区间，不是昨天 23:59。
本周至今使用 week_start 至 context.now；完整上周使用 previous_week_start 至 previous_week_end。
本周与上周同期比较分别查 week_start 至 context.now、previous_week_start 至 previous_week_same_time_end。
周同比用两次 activity_stats，comparison 都设 null；previous 只代表紧挨的等长时段，不代表上周同星期同期。
比较注明各自英国日期和截止；夏令时切换按边界的明确偏移计算实际时长，不移成固定 168 小时或滚动七天。
今天上午为当天 00:00–12:00，实际截止不晚于本轮提交时间。用户明确具体时间则使用具体时间。
同名且无法区分才提问，不逐次确认普通查询。
context.can_query_other_cm 为 true 才能跨 CM 查询。Owner 点名多个 CM 时，用 resolve_staff 分别解析姓名，或使用服务端 available_scopes 中的真实 cm_id；不能把在一个账号里搜索这些姓名当成读取这些人的聊天。每个所需账号分别传 cm_id 查询，保留各自时段与来源，并在最终回答合并；其他 CM 名字仅是本人聊天对象时，不切换账号范围。
今天默认只用于独立新问题。“这些事情/刚才那些/进度怎么样”先沿用上一轮实际事项，跨午夜也不变成只查新一天。
追问当前进度时，原时段用于定位事项，截止延至本轮 context.now；不必先重复总结旧截止之前的全部材料。
最近回复若只有 0 条消息或连接情况，继续定位最近含具体业务事项的一轮；不要要求用户重新复制刚谈过的事项。
history 中的 requires_refresh 表示原事项仍来自已核验记录，但最新进展须重新查询；从原时段起点查至本轮时刻，不能用新一天 0 条否认原事项。
coverage_refreshed 表示读取情况更新，不表示之前的事项消失；旧回答中的读取统计和告警不能照搬为当前事实。
总结、检索和统计默认 audience=all；只有用户明确说达人、指定达人或明确追问这些达人时才用 creators。
普通“昨天整天/今天消息”不能沿用此前的达人筛选，也不能将旧达人报告的 0 条当作全量没有消息。
第二条/这个达人指上一轮实际卡片引用，不擅自更换范围或按易变排序猜人。
只看重点、样品相关等短追问沿用上一轮实际报告的人员、时段与未回复口径，只改变本轮明确的筛选。
只有明确延续上一轮的问题才复用上一轮 scope 中的对象；普通全量问题不能用历史单人范围代替全部负责名单。
给第二条写英文回复按上一轮 event_index 找到实际编号；卡片分组不改变编号，不能按某个分组的位置猜引用。
上一轮是分类列表时，“第二项/第二类”使用 section_index 的稳定编号及真实 message_refs，不按新排序猜。
一类包含多个对象、无法确定回复谁时，列出实际对象再追问；不能任选一条或给多个人自动发送。
上一轮 scope/window 是已执行查询的说明，不是新问题的强制筛选。用户改变时间或范围时按本轮要求重新查询。
“改成上周”只改变上一轮时段；“昨天所有聊天”清除旧达人/单群筛选，覆盖本人全部会话。
最新进展单独标明查询截止，不改写原时段结论。
