# 达人识别流程与入口

本手册用于名单导入、新人员自动识别和已确认达人的账号补配。任务准备时固定六份手册版本，执行时只读取对应阶段；入口由服务端决定，不增加一次模型路由请求。

## 三个入口

| 入口 | 处理对象 | 固定处理方式 |
| --- | --- | --- |
| CM 导入名单 | 一位负责人提供的 handle 名单 | 规范化、去重、复用已确认关系，再找相关会话和真实人员；分别核对身份和账号 |
| 新加入人员 | 同步发现的联系人、群成员或私聊对象 | 先登记中性联系人；有可读证据后判断身份，不能因进群直接认定达人 |
| 已确认达人 | 已有达人身份的人出现新材料或新账号 | 复用身份，只判断新增账号；不重复证明已有精确人员与账号关系 |

Curva 等全量账号目录只是候选目录，不能当作 CM 的负责名单。导入目录本身不建立身份、人员或负责人关系。CAP、非 CAP 不再作为识别分支。

## 固定顺序

1. 校验来源和读取权限，登记本轮人员或账号及处理状态。
2. 检查既有身份、账号关系、人工拒绝与冲突。复用已确认事实，不为重复关系调用模型。
3. 准备群名、真实成员、本人消息和完整问答；私聊与群都纳入目标流程，不要求先命中自报账号关键词。
4. 独立判断“这个人是否是达人”和“哪些账号是这个人的”。可在一次请求中输出两个结论，不必增加一次模型调用。
5. 仅补查阻碍判断的材料。新证据仍不足时等待，不反复用同一份材料付费猜测。
6. 后端重新校验权限、来源、版本与关系冲突，分别提交可成立的身份和账号结论。新人自动身份确认须有明确本人业务证据，并达到 `max(95%, 功能配置阈值)`；高分不能替代证据。
7. 身份确认后，独立进入账号补配、负责人匹配、群分类、维护优先级及事件补算。任何一个下游暂未完成，不撤回已成立的身份。

达人身份可以成立但 handle 未知。导入某个 handle 未匹配上，也不能据此判断相关人员不是达人。纯目录中没有对应人员的账号留在目录，不创建空壳联系人。

## 按阶段读取手册

| 阶段 | 使用文档 |
| --- | --- |
| 选择入口与准备任务 | 本流程、识别材料与补查规则 |
| 未确认人员身份 | 达人身份证据规则；同时判断账号时加人员与账号关联规则 |
| 已确认达人补账号 | 人员与账号关联规则、识别材料与补查规则 |
| 正式写入与后续触发 | 入库与后续处理规则，由后端执行，不交给模型写库 |
| 修改规则与发布验收 | 历史案例与识别验收，不随每次生产请求发送全文 |

入口由服务端已知来源决定，不另用 AI 判断“该走哪个入口”；模型负责业务证据含义，不决定读取权限或启动任务。

## 处理状态

“已确认”表示身份成立；账号是否匹配单独展示。“待核实”表示有材料但存在实质歧义；“等待材料”表示缺本人文本、问答或相关会话。“不支持本项结论”仅针对本轮身份或账号命题，不能扩展为永久排除。

授权失效暂停读取；结构损坏才属于结果校验失败。请求已发出但结果未知时保留回执，不自动重复收费。新消息、完整问答补齐、相关群名变化、人工更正或显式复核才推进受影响任务。

## 运行边界

名单导入仍保留原有候选会话、人员核验和批次进度，身份与账号改用本组统一规则；新人复用现有持久化任务和 Worker。已确认达人仍按账号证据门槛补配新账号，不增加自评分门槛，不重写身份或负责人。

新人身份使用现有“达人—handle 匹配”的凭证、开关和队列，以独立任务用途区分身份识别与账号补配。名单导入沿用原凭证和显式启动的批次，不新增 Key 配置，不修改现有阈值。

流程和入库手册是全流程发布条件，其他手册按依赖阶段检查。所需手册处于草稿或停用时，不发新的模型请求、不使用旧规则降级处理；重新发布后按原有队列继续。正常编辑已发布内容不改变已准备任务的固定版本；保存不触发全库重跑。

历史案例手册只用于开发验收，不随每次生产请求发送，不因其草稿状态暂停生产。没有恢复退役的全库泛扫、旧候选页面或“身份→负责人→handle”三阶段流程。
