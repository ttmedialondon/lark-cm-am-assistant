# 连续追问与最新进展

适用于“这些事情怎么样了”“只看付款”“给第二条写英文回复”等延续性问题。独立新问题按本轮范围重新理解，不能被上一轮单人、达人或单群范围限制；“改成上周”只改变原时段，“昨天所有聊天”清除旧达人与单群筛选。

先定位最近真正包含具体业务事项的一轮。最近一轮只有零消息或连接情况时继续向前找，不要求用户重贴事项；跨英国午夜仍沿用原事项，不能用新一天零消息否认旧事。`requires_refresh` 表示原事实可作定位但最新进展要补查；`coverage_refreshed` 只是读取情况更新，不表示事情消失，也不能照搬旧告警。

“第二条／这个达人”按 `event_index` 或 `section_index` 的稳定编号找实际引用，不按分组位置或新排序猜人。一类包含多个回复对象而无法确定时列真实候选再区分；只看重点、样品相关等短追问沿用原人员、时段、未回复口径，只改本轮明确筛选。有效达人报告用 `filter_events`，全消息材料用原结果或正文检索，不能伪造 `result_id`。

先找到具体付款、样品等事项，再读同一事项后续。`read_message_context` 或 `read_event_context` 的 `latest` 可核对有限最新问答，但不是全部后续。需完整跟进时，使用工具或 `history.section_index.sources` 返回的真实 `chat_id`，从原事项起点查至本轮 `context.now`；缺编号时先用真实消息引用读上下文或目录定位，不能从群名拼 ID。有限邻接消息仅作线索，不自动属于同一事项。

补查围绕缺口进行，已有材料足够就回答；连续重复没有新增材料时停止并说清未获证实的部分。原时段结论与最新进展、实际截止分开，逐项说明已完成、仍待跟进、尚未见后续；未见后续不等于没发生或没处理。展示按本轮意图重判，问依据或进度不沿用上轮的回复按钮，需要起草时转 `reply-writing`。推荐模板：`answer-list`。
