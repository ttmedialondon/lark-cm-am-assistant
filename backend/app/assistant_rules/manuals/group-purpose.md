# 群用途判断

## 目标与分类

判断输入一个群的长期或已明确建立的主要业务用途，不给单条消息分类。每个规范化群独立处理，共享群不按达人重复分析；私聊不分类。已确认达人、handle、负责人和群用途是独立事实，不通过本次分析改写。

主用途只选一个，沿用现有枚举：

| `purpose` | 判断条件 |
| --- | --- |
| `support` 客服群 | CM/AM 为个人或少数共同合作达人提供专属服务，持续处理账号运营、样品物流、广告码、佣金及履约。多人共用仍可成立，没有“只能一位达人”的人数门槛。 |
| `community` 机构达人群 | 机构、平台或运营方长期面向一批达人的综合运营、广泛通知及交流，不限单一品类、品牌、课程或活动。也包括长期本地多品牌、多品类机会渠道；不代表由 TT Media 管理，外部组织可作标签。 |
| `training` 培训群 | 持续承载课程、培训项目、任务、作业、录播和教学答疑，或开群说明已明确建立培训用途。偶尔转发培训通知不够；有期限的成长课程仍可为培训。 |
| `category` 类目群 | 围绕明确品类、品牌或产品线持续推品、选品、寄样及内容合作。长期品牌 Creator Community 也可属于此类，品牌名称用标签补充，不增设品牌主类。 |
| `campaign` 活动群 | 专为一个明确活动、比赛、项目或 Campaign 建立，具有专用范围、活动标识、时间或规则。已结束的活动仍按用途分类，标记历史活动，不表示仍可发送。 |
| `unknown` 未确认 | 主要用途不清、冲突、材料不足或不在达人群用途范围。商家与机构谈佣金总包、样品审批、商务合作或介绍某位达人，不因提到达人就成为客服或类目群；有依据时加范围外标签。 |

## 判断顺序

1. 结合群名、成员结构、开群／用途说明、跨时段真实沟通及近期变化，确定服务谁、持续处理什么。成员数量、已确认达人数量都不是硬门槛。
2. 区分本群用途和某次消息内容。客服群转发推品、优惠券、课程和报名，仍可能是客服；邀请加入另一个培训群不等于本群用于培训。
3. 用真实历史核对名称。Live、Flash Sale、CAP、VIP、品牌、handle 或 Lark 主题群形态都不直接决定用途；CAP 不再是业务类别。明确的整体用途转变可形成新建议，人工结果仍优先。
4. 长期品牌群不因一次促销变成活动群，综合群不因一条产品消息变成类目群。名称含 Community，但实际围绕一次比赛的规则、排行榜和收尾，也可为活动群。
5. 群内有达人、CM 或 handle，只提供群场景线索，不证明所有成员身份、账号归属或负责关系。商家、机构代表之间的商务沟通要与达人服务区分。

## 群名的作用

群名是强辅助证据，不要求成员主动声明用途。姓名／handle × TT Media、Academy／Incubation／Growth／Masterclass、品牌＋Creators、活动日期／Challenge／Championship、宽泛 Creators Hub 分别可支持对应方向，但要结合成员、明确用途说明或实际业务原文，不能做关键词映射。具体边界见入库手册案例。

名称与历史矛盾时以真实用途为准，关键歧义无法解释则未确认；群名不清晰也可由稳定沟通确认。历史离开机构、活动过期或外部运营影响路由，不改写已明确的历史用途。
