# 负责人关联与案例

## 自动新增，不自动改写

模型逐位提出关系结论，后端决定能否写入。自动新增须同时满足：

1. `responsible + current + person`，置信度达到本功能配置阈值（默认 95%）。
2. 有有效的真实支持引用，无反证及引用校验错误；未遗漏关键交接或解除，支撑回复具备实际上下文。
3. 达人身份、候选及证据当前有效；该候选能唯一对应一个有效接入账号。
4. 不存在该关系的人工解除记录，且通过现有权限、材料版本与并发写入检查。

高置信度不豁免任何条件，文档不能授予权限或改变阈值。证据仅限某账号、时间不明或存在关键缺口时，保存结论待核实，不自动扩成人级关系；一名候选的引用问题不影响其他合格候选。

已存在的关系直接保留，不重复创建，不因弱结论降级或撤销。多位 CM 可同时新增，分别判断并建立关系；具体职责与证据保留在匹配结果中，新增一人不挤掉其他人。明确退出或交接也只形成复核建议，不自动解绑、转移、结束旧关系或恢复人工解除。人工确认的事实不因本次规则发布重新证明。

## 判断示例

以下为说明规则的虚构简例，不是本次新增审阅的真实聊天、生产结果或准确率测试。实际结果以完整材料和服务端校验为准。

| 材料 | 判断方式 |
| --- | --- |
| 同事在目标达人群介绍“CM1 以后负责你的选品和佣金”；达人随后向 CM1 提交问题，CM1 落实并回复结果，近期仍在跟进 | 可支持 `responsible/current/person`，职责为选品／商务；不是因同群或称呼 CM 就确认。 |
| 目标达人由 CM1 跟进样品、CM2 跟进直播；双方各有明确分工及当前承接 | 分别判断，可同时负责；不能强制挑一个主负责人。 |
| CM1 群发产品链接，并对达人说“需要的话我可以帮你催样”，没有后续承接 | 营销或协助意愿不足以证明负责，通常为 `assist` 或 `insufficient`；重复发链接不升级。 |
| 旧记录明确 CM1 为个人 CM，后来介绍 CM2 帮助直播设置 | 不直接认定 CM1 离任；核对 CM2 是专门协助还是持续负责。CM1 当前延续不清时标时间待核实，不凭沉默结束。 |
| 早期有 CM1 连续处理业务，之后没有近期材料，也没有明确退出 | 可证明曾承担责任，但当前延续仍需判断；不能仅凭没看到退出自动新增为当前关系，也不能判已离任。 |
| CM1 明确说“之后全部转给 CM2，我不再负责”，CM2 接手且继续实际对接 | CM1 形成历史／交接复核建议，既有关系不自动删除；CM2 独立核验，不能只凭被提及就关联。 |
| 群名含达人账号，CM1 是群成员且经常发公告 | 只能说明群场景和活动，不能单独确认 CM1 负责。 |
| 系统已有 CM1 正式关系；本包只有“谢谢”和一条广告 | 保留已有事实，不要求重新付费证明，也不据此新增职责或撤销关系。 |
| CM1 的支撑引用缺少关键父消息；CM2 的完整分工和当前业务证据有效 | CM1 保留待核实；CM2 可独立通过，不让一个弱候选拖失败整批。 |

## 执行约定

三份手册共同指导一次负责人判断请求，不拆成三次模型调用；输出字段与写入协议仍由现有代码定义。任务固定手册快照，编辑影响之后准备的任务，不在执行中混用规则；草稿或停用手册不由旧固定 Prompt 静默替代。

普通编辑不新建任务。恢复发布只续跑因手册停用暂停、且尚未实际调用的既有任务；已调用的暂停结果留待人工核实，不自动重复付费。不全量重跑、不修改现有确认关系、不发送 Lark 消息。正常新材料继续使用原队列、配置和缓存机制；实际新增有效关系后，才由既有流程接续“我的达人”、维护优先级及最近七天事件补算。
