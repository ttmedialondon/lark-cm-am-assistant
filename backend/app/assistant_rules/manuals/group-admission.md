# 群用途入库与边界案例

## 输出与自动入库

只返回 JSON 的 `purpose/confidence/tags/refs` 四字段，无解释、推理过程或长理由。`tags` 最多 8 项，每项不超过 80 字符，记录有依据的品类、品牌、课程／活动、外部组织、历史活动或范围外事实，不含私人地址、电话、支付信息和完整聊天。`refs` 最多 8 项，不编造引用。

`confidence` 为 0–1，不是系统准确率。名称、结构、完整原文一致且无关键反证时可给高分，不要求固定自我介绍或重复声明。证据不足、用途冲突用 `unknown`，是正常结果；不为入库或凑齐类别强行高分。

自动入库由现有程序执行，必须同时满足：

1. 用途明确、非 `unknown`，达到本功能 API Key 配置阈值，默认 95%。手册不改变实际阈值。
2. 至少引用一条真实正文，且所有支撑引用有效、关键回复父链完整。只有 `G1` 的建议不能自动入库；残缺背景不能支撑高分。
3. 群、相关达人、当前授权、原文与任务版本仍有效，结果未被更晚任务取代。
4. 不覆盖任何人工分类，无论是否锁定；也不覆盖任何来源的锁定结果。仅允许更新此前未锁定的 AI 分类。

弱建议和 `unknown` 不替换正式用途，人工 `unknown` 也受保护。自动写入保留 AI 来源、置信度、任务和审计，不伪装人工确认。分类用于角标和群发选择，不授予发送资格、不发送、不改身份／账号／负责人。

## 典型边界

以下是根据现有协议整理的说明案例，不是本次新增生产群审阅或准确率验证。

| 材料 | 判断边界 |
| --- | --- |
| “Alice × TT Media”，已确认达人成员，跨时段主要由 CM 处理其样品、账号和广告码；夹有活动邀请 | 可支持客服；不因转发活动改成活动群，不要求本人说“这是客服群”。 |
| 两位合作达人与 CM 共用一个长期服务群 | 可为客服，不能用达人数量超过一人否决；仍须实际服务证据。 |
| “Acme Creator Community”，长期仅围绕该品牌选品、样品与内容合作 | 可为类目，Community 不是综合群的固定映射；不增设品牌主类。 |
| “Creators Community”，原文持续围绕同一次挑战赛规则、排行榜及结束通知 | 可为活动；已结束加历史活动标签，不因此改成综合群，也不表示可以继续群发。 |
| 八周成长课程，持续每周作业、录播和教学答疑 | 可为培训，不因有期限而变成活动；单次选品会议或一次课程广告不够。 |
| 本地多品牌、多品类的长期机会渠道，由外部机构运营 | 可为机构达人群，补外部组织／地区标签；不能声称由 TT 管理。 |
| 商家与机构核对达人名单、样品审批及佣金总包，没有实际达人服务场景 | 通常范围外、未确认；出现 handle 或达人姓名不够。 |
| 群名明确，但全部正文过期或只有一条缺父消息的回答 | 不靠名称给出可自动入库结论，等待完整证据；其他完整且一致的证据存在时独立判断。 |
| 模型 98%，但唯一支撑回复缺原问题；另一个群 96% 且证据完整，但已有人工分类 | 前者保留建议，不能保留旧分数直接入库；后者保留人工值，分数不授权覆盖。 |

## 执行约定

三份手册共用一次原有请求。输出、取材上限、阈值及权限由程序执行，不由文档改变。新准备任务固定手册快照，已冻结任务沿用旧版本；手册草稿／停用时暂停依赖流程，不用静态 Prompt 静默兜底。

编辑不建全库任务、不改正式用途、不重放历史；恢复沿用原队列和已保存结果，不自动重复付费核验结果未知的请求。正常新材料沿用现有缓存、凭证、并发和人工入口，相同材料不因共享群、多位达人、正常成员刷新或普通新聊天重复调用。
