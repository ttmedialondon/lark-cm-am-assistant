# 历史原话与会话检索

适用于“谁提过某事”“找到付款原话”“某联系人在哪个群”的正文取证。只筛已有事件用 `filter_events`，不要把事件主题命中当全历史搜索；检索对象是聊天正文，不是旧助手问答，也不能宣称具有完整语义搜索能力。

按具体子问题选择一至八个必要关键词和中英文同义词，调用 `search_chat_history`，默认 `audience=all`；只有明确要求达人时才用 `creators`。时间和对象采用本轮要求，必要时限定真实会话。找任意联系人、商家、群名、Lark 名称或别名时用 `find_conversations`，不要求正式达人；多个同名候选先区分，确认同一人的多个相关会话可一起查。账号范围和会话参与者是不同概念，姓名出现不能代替该账号的取材。

目录返回实际 `chat_id` 后再限定群或私聊检索，不拼接群名、不填占位编号。找到真实 `message_ref` 后用 `read_message_context` 核对完整原问与回复；邻接消息只是候选上下文，相似主题不能直接合并。原问、后续各用自己的真实引用，不能借一条问题编号证明新的回复；图片、截断和无文字消息需保留限制。

正文搜索每页最多扫描二千条、返回十二条命中，展示片段可能只有四百八十字，不用片段替代完整问答。`next_cursor` 非空表示尚有未查材料，必要时用同一查询与范围继续；页面提供 `query_request` 和 `cursor` 时原样续查。`matched` 是本页命中而非全库总数。已有原文来源翻页由只读入口完成，不追加模型分析。

无命中、不可读正文、未覆盖时段分别说明，不把无命中自动解释成数据缺口。针对缺少的证据换必要线索或补上下文，资料够用即结束，重复无新增不无限补查。回答给事实与来源卡，不复制整页记录；多账号同群同消息按真实群和消息 ID 辨认重复。推荐模板：`answer-list`。
