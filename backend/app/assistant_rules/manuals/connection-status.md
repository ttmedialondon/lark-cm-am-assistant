# 账号连接与消息可用性

仅适用于用户明确问“账号连接正常吗”“消息能否查看”“为什么这些消息不可读”。业务进度、达人未回复、付款或样品后续、新一天零消息均不自动调用连接检查；先使用对应业务手册，不能把后台机制当业务事项或推断事情未处理。

调用 `get_sync_status` 读取现有状态，工具只读，不刷新令牌、不触发授权或回填。按返回的人员、时段与已确认原因判断可用性，不猜测用户少授权，也不自动切换账号或模式重试。没有消息、没有事件、部分可读、分析中、失败、账号失效分别说明；一次扫描结束只代表当前可读材料已读完，不代表来源已完整同步。

已确认的账号失效单独提示检查账号连接；群受限、历史时段未同步、最新同步中、无文字附件和正文不可读分别保留，不一概称重新授权。只有系统明确确认群限制才这样表述，未知原因说明暂不可读。完整历史回填后历史起点可为空，正常增量同步不使既有历史事实自动失效；读取情况刷新也不代表业务事项消失。

原文改变、删除或材料失效时不继续照搬旧结论；来源仍有效的历史事实可定位追问，但最新进展用业务工具补查。正常读取状态推进不能当正文变化，不能把旧告警当当前事实。已发出但结果未知的请求不主动重做；不要为连接诊断反复轮询模型，也不尝试绕过已确认的不可读原因。

普通回答简短说明业务可用性及用户实际需要的下一步，必要缺口最多一句，其余留给界面折叠项；不主动列首次同步、回填、水位、队列、读取条数或百分比。原聊天里的技术故障仍可作为真实业务事项处理，与本助手诊断分开。状态结果通过真实 `data_refs` 交卡片，无原消息来源时 `sections=[]`。推荐模板：`answer-comparison`，仅采用其中状态说明，不凑统计比较。
