# 聊天总结与长材料归纳

适用于今天、昨天、指定时段的聊天总结、重点分类，以及用户明确要求全量审阅的长材料。仅找原话时用 `history-search`，行业分析先用 `business-analysis`，不默认做每日待办。普通独立新问题未指定日期时，取英国今天零点至本轮提交时刻；上午截止不晚于当天十二点与提交时刻，明确日期优先。

调用 `summarize_messages`，默认 `audience=all`，包括群聊、私聊、所有发言人及未识别、未分配、员工、商家、机器人消息；本人聊天不等于本人发言。仅明确要求达人时用 `creators`，复用有效达人事件报告；普通全量问题清除旧达人或单群筛选。特定对象先定位真实人员及会话，同名未区分时才追问。多账号按工具返回的实际范围分别取材，不以搜索姓名冒充该人的全部聊天。

全消息一次请求由系统完整分页，长正文按会话分段并合并，无需用户继续翻页。每段围绕原问题保留具体事项、责任人、明确时间、完整问答及支持或反驳结论的材料；长消息 `text_part` 合并还原同一条原文。相似主题不等于同一事项，不把甲的进展安到乙身上；机器人通知不改写为本人承诺，附件不猜内容。

分段 `items` 各自保留 `evidence_refs`，合并沿用对应关系；当前批次 R 编号仅放引用字段，旧摘要没有逐项证据时先查原消息。摘要与事项文字合计不超过工具要求的上限，不靠删除反例或错误引用换取通过。分页重复、缺页、来源变化或提前结束不能称完成；`scan_complete` 仅表示当前可读材料读完。新消息进入下一次查询，不改写本轮截止。

回答按实际主题列对象、进展和下一步，普通分类用 `source_mode=compact`、`reply_enabled=false`，必要依据集中折叠；仅明确要求原话、核对或回复时按回答规则改模式，不能为精简清空逐事项引用。无业务文字可简短说明；未见回复不等于未解决。明显影响结论的缺口最多一句，不主动罗列后台统计。推荐模板：`answer-list`。
