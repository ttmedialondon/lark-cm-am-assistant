# 活动统计与时段比较

适用于消息量、实际联系人数、日常活动和时段比较；不用于推断寄样、付款、履约或全局唯一未解决事项。调用 `activity_stats` 使用数据库数字，默认 `audience=all`，按 `day/person/conversation` 分组；只有明确达人问题才用 `creators`，按 `day/creator` 分组。

时间使用服务端英国日历边界与带时区 ISO 日期。今天为当天零点至提交时刻，昨天用 `yesterday_start` 至 `yesterday_end` 半开区间，结束不是二十三点五十九分；本周从 `week_start` 周一零点起，不是滚动七天。上午取零点至十二点，实际截止不晚于提问；明确时段优先。

本周与上周同期分别查 `week_start→context.now` 和 `previous_week_start→previous_week_same_time_end`，两次 `comparison=null`；完整上周用 `previous_week_start→previous_week_end`。`comparison=previous` 只比较紧挨的等长时段，不代表上周同星期同期。使用工具给出的明确偏移；夏令时不能强移成固定一百六十八小时，墙钟不存在或重复小时按实际经过时间处理并说明口径。

联系人数只认本人私聊、明确 `@` 或回复的实际对象，不拿群成员数代替；达人模式保留达人发言及明确互动口径。工具总量与本页分组不同，一条多人消息可能进入多个组，分组不能相加当总量。多 CM 可见同群同消息有重叠，分别保留人员数字，不能相加声称公司去重总量；没有工具去重结果时明确不能推得。游标未空按原参数续查，避免把本页分组冒充完整列表。

无消息、正文不可读、同步未覆盖是不同情况；没有匹配不自动等于缺口。比较先核对两段日期、截止、受众和分组口径是否一致，再解释真实差异，不凭数字断言效率、因果或商业效果。回答简述关键比较并交统计卡；没有原消息引用时 `sections=[]`，真实查询编号仅放 `data_refs`。推荐模板：`answer-comparison`。
